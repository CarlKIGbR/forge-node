## Betriebsleiter conditions c) and d)
### d) audit sealing — **met in code and tests, gate D stays `met=False`** (the flip is a one-line commit after the review)
**Protocol** (design §8.3, `audit/log.py` docstring): live file `+a`, sealed file `+a +i`; a new log file is built inside a root-only (`0700`) generation directory, receives `+a` BEFORE the directory becomes reachable (so no other uid ever holds a descriptor that predates `+a`); rotation = repair a damaged tail → add `+i` (from here no descriptor, however old, can write) → read the final head and sha256 → build the successor with its `chain_link` (prev seq/hash/sha256/bytes/damaged bytes) → `+a` → make reachable → atomically replace `CURRENT`. **No `chmod`/`chown`/`truncate`/`rename` is ever issued on an append-only inode** (`test_seal_never_calls_chmod_on_append_only_inode` spies on every call). Appenders (privd for `priv`, the agent for `audit`) never rotate or repair `CURRENT`; a sealed or flagless live file is `AuditDown` for them. Single writer: flock around the whole critical section + a mutex; the head cache is only a *starting point* (the chain is followed forward from it; it ends where our own `O_APPEND` write ended). Crash recovery is idempotent from self-describing states; `audit-init`, rotation and purge are all crash-safe.
**Kernel facts** (observed on the host's ext4, kernel 7.0.0-31, asserted by `fsproof` and by `test_fsproof_*`): `+a` ⇒ open-for-write without `O_APPEND`, chmod, chown, truncate, rename, unlink, link, fallocate (punch/zero/collapse/insert), `RWF_NOAPPEND`, clearing `O_APPEND` then pwrite all fail; **a descriptor opened for writing before `+a` was set can still write afterwards** (informational in the proof; the protocol is built so it cannot exist); `+i` refuses every write through any descriptor, however old; `fsync`/reads keep working.
**Tests on a REAL filesystem** (throw-away container, `--cap-add LINUX_IMMUTABLE`, bind-mounted directory of the host's ext4; `scripts/run-tests.sh` turns a missing/non-working real filesystem into a FAILURE, never a skip): live writer processes holding descriptors across rotations (`test_rotation_real_ext4_chattr_a_live_writer_descriptor_cannot_append_after_seal`), a hostile agent-uid opener hammering the directory during 25 rotations while it must observe ≥ 8 generations and never find an unflagged writable file (`test_rotation_has_no_writable_window_on_live_file`), **SIGKILL before AND after every mutating system call** of a rotation (26 calls on the priv log, 27 on the agent log) with the invariant "a flagless file exists only in a `0700` directory" checked after each, recovery rolls forward / is idempotent from each, and **the recovery itself killed at every one of its calls from every rotation state** (`test_recovery_itself_is_crash_safe`: all 26 states), the same sweep for **purge** (`test_purge_killed_at_every_step…`) and **init** (`test_init_killed_at_every_step…`: 23 calls × before/after), plus hostile appends (rewinding forgeries, invented chains, megabytes of junk, torn fragments between repair and seal) — see N3-15.
**What needs root, and how `doctor` proves it on the node.** Root is needed for `chattr +a/+i` (CAP_LINUX_IMMUTABLE), `chown`, and for forking processes that drop to the agent uid; the test container runs as root with exactly that capability on a host-ext4 directory. What a container cannot show: (1) the **capability set of privd's real unit** (`CapabilityBoundingSet=CAP_LINUX_IMMUTABLE CAP_CHOWN`, `ReadWritePaths=…`) — `doctor` → `privd selfcheck audit` runs `fsproof.prove()` **inside privd's own unit against the real log directories** (canary in a root-only scratch directory next to each log; 23 checks incl. all the escape routes above) and `peek()`s both live logs; `privctl audit-init` runs the same proof first and refuses to create a log on a filesystem where it fails; (2) **filesystems other than ext4** (xfs/btrfs untested; tmpfs and overlayfs are refused by the proof — observed); (3) **power-loss reordering** (SIGKILL is not a power cut; the order file-fsync → `+a` → `fchmod dir` → fsync dir → `CURRENT` rename is chosen for ext4's journal ordering and is *recorded as an assumption* — a hostile unsynced byte before a power cut would show up as a loud `chain_link` mismatch, never silently).
### c) unit resolver — **N3 owns the resolver ⇒ REJECTION implemented; gate C stays `met=False`, all unit ops stay disabled**
`privd/resolver.py` computes the complete action-specific transaction (forward closure F, conflicts C, stop-closure S, extras X) from the live unit graph and **rejects (as a protected hit, like an incomplete resolution) any unit in the effect set that uses `OnSuccess=`/`OnFailure=` or an isolate `On*JobMode`, and any requested job mode other than `replace`/`fail`**. It does not follow those edges (N6/N7: `test_resolver_follows_onsuccess_onfailure_recursively…`, `test_t3_unit_*_requires_frozen_ack…` must NOT exist yet — pinned by `test_gate_c_resolver_half_tests_exist_and_gate_c_is_still_unmet`). Reachable only through `privctl unit-closure`; no `unit.*` op exists in the op table. **On carlgpu2 every start/restart is denied** (an inactive oneshot with `OnFailure=` — `systemd-fsck-root.service` — is in every forward closure; live proof below); stop/disable of an unprotected unit is allowed by the resolver (nothing can call it).
Design correction found by that live proof (design §4.3.1 "N3 refinement"): the literal "any member of the closure is protected" rule denies every real unit including the design's own example; the effect set is state-aware **on the start side only** (an active dependency is left alone); everything a transaction would *stop* (conflicts, stop-closure incl. `RequisiteOf`, restart/reload propagation, `StopWhenUnneeded=` dependencies) is judged whatever its state is now, because it can change between check and action — the op (N6) must re-resolve in its worker under the effect lock and compare `closure_sha256`.

## Deviations from the design text, and decisions for the Betriebsleiter
1. **Resolver effect set** (above; design §4.3.1 updated). All unit start/restart ops stay denied on carlgpu2 until N6 follows `OnFailure=` edges.
2. **Hub cross-check relaxed in two narrow ways** (needed so that the node does not get quarantined by its own legitimate denials): a `denied` job with an *agent-local* reason (`DENY_TIER_DISABLED`, `DENY_AUDIT_DOWN`, `DENY_STALE_LEASE`) and NO priv record at all is accepted — privd never saw it, nothing ran; a `failed/FAIL_PRECHECK` job with a `denial` and no `intent` is accepted. Anything else (a privd reason without privd record; an intent without result) still quarantines. Please confirm.
3. **privd `ReadWritePaths` is `/etc/forge-node`** (design said `/etc/forge-node/policy`): a unit grants directories, and privd must create `LOCAL_STOP` there (design 4.4 updated).
4. **`selftest.noop` is the only executable op**; it is mutating, T1, `full` profile, `requires_plan`, and exists to give the pipeline, ledger, worker, fence, effect lock and reconciliation something real to run.
5. Light T0 probes through privd are limited to 3/min per probe (the agent's own engine limits 2/min, so the engine trips first).
6. **Not in N3, needed by N4's acceptance text:** `privctl selftest-bypass` (the N4 STOP test sends a hub-signed T1 dry-run straight to the socket) — a root command that sends a given signed envelope to the socket; trivial on top of `PrivClient`, but N4's, not N3's. The pytest direct-socket bypass tests are done (N3-3, N3-13).
7. **Hostile agent uid on its own log** (accepted residuals, fail-closed): it can hold `audit.lock` (flock) — appends/rotation of the agent log then fail with `AuditDown` after 10 s per attempt until the agent unit is stopped (privd still starts: `recover_all` tolerates it); it can append junk to its own `0660` file (bounded per file by `LimitFSIZE=128 MiB`; sealed files cannot be purged for 90 days); after a failed `fsync` the Appender drops its cache and re-reads, but the record may exist although `AuditDown` said "nothing written" (harmless duplicate; an orphan `intent` raises the hub's 10-minute `intent_open` alert, not a quarantine); a crash between the `CURRENT` swap and the `recovery` record loses that record (the state afterwards is clean, `verify` passes).
