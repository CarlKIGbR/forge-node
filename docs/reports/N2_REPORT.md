## Standards applied
- **One guarded path without optional guard inputs.** Every read goes `agent loop → T0Engine.execute | T0Engine.sample → (collect | probe) → sanitize.finalize`; the probes are reachable only through `wire.handle_request`/`probe_main` → `probes.run_probe`, which re-applies the blackout window itself. Limiter, probe transport, environment, spool, hub-cert provider, pins, `owner_uid`, `expect_uid`, `ssh_keygen`, clock are **required** arguments; `execute(op, tier, params)` has no flags. Pinned by `test_no_function_in_the_t0_layer_or_agent_has_an_optional_guard_input` (AST scan: no guard-named parameter has a default; it caught `_PinnedConnection(pins=())` while writing, and the **independent review** found the sampler as a second read path — now `T0Engine.sample`, only the engine calls `take_sample`: `test_sampling_goes_through_the_engine_guards`), `test_engine_requires_its_guards_as_arguments`.
- **Evidence re-observed before irreversible/trusting decisions:** policy file mode/owner/nlink on the *open descriptor* at every load, the policy directory, `allowed_signers` (also part of the reload cache key); the command binary, **every program it starts and every directory above them** on **each** `run()`; the privd peer uid via `SO_PEERCRED` on every connection **before** sending; the hub leaf pin on every new connection **before** the first request byte; the blackout window inside the probe at execution; git never opens the repository's config at all (generated snapshot, no scan-then-run); spool segments `lstat`-ed (regular, our uid, one link, expected name) immediately before they are unlinked; a new policy is signature-verified at the moment it replaces the old one and any failure means *no* policy (never the older file); symlinked reads are resolved and the *resolved* target is checked again, then opened without following links.

**Git snapshot path escape.** `_git_snapshot` built the loose ref file with `os.path.join(snap, "refs", "heads", branch)`; the branch came from `.git/HEAD` (`ref: refs/heads//<abs path>`), validation only rejected `..`, so for an absolute component `os.path.join` discarded the snapshot prefix and `open(..., "w")` overwrote a file outside (the reviewer's canary got 40 `a` and the response said `ok:true`). Reproduced first (`os.path.join("/snapshot", "refs", "heads", "/x") == "/x"` is asserted in the test as the mechanism), then fixed in three independent layers:
1. **Ref names are validated with git check-ref-format semantics on a stricter charset** (`probes.valid_branch`): only `[A-Za-z0-9._/-]`, length 1–200; no leading `/` or `-`; no trailing `/` or `.`; no `//`, no `..`; no empty component, no component starting with `.` or ending with `.lock`; not `@`; so also no NUL, backslash, space, control character, `~ ^ : ? * [ @{`. A HEAD that names anything else is **rejected**: row `error: malformed_ref`, `dirty_status: rejected:malformed_ref`, `branch`/`rev` withheld, git is not started. 2. **All snapshot writes go through a directory descriptor** (`t0/confined.py`): `mkdirat`/`openat` relative to the snapshot's fd, each component validated (`[A-Za-z0-9_][A-Za-z0-9._-]{0,99}`: no `''`, `.`, `..`, `/`, NUL, backslash, leading `.`/`-`), directories `O_NOFOLLOW|O_DIRECTORY`, files `O_CREAT|O_EXCL|O_NOFOLLOW`; a snapshot that cannot be built is removed and reported `failed:snapshot`. `_git_snapshot` additionally re-checks the branch itself (so a hole in layer 1 is still contained).
3. **The same helper now writes the agent's staged policy blobs** (state dir → `staging` → tmp file → rename inside the descriptor; names built from the integer serial 1…999 999 999 only; a `staging` replaced by a symlink is refused).

12. LOW sampler was a second T0 read path → `T0Engine.sample()` (see Standards).
13. LOW dead NFS mounts leaked a thread per call → hung mounts remembered 10 min + 8 s `df` budget.

15. Tests that did not prove their names (`probe_main` assertion always true, source-grepping TLS test, certificate "presented" not asserted) → replaced by behaviour tests; new tests for `commondir`, symlinks, odd names.
Round 2 (against `git diff 9e02414..HEAD` as of its launch): the reviewer confirmed 14 of 15 as fixed and could break one — finding 2 was only partly fixed (`/proc/mounts` is a link to `self/mounts`, which the resolved-path allowlist did not accept; `inv.disks` reported `nfs_mounts` as `ok` and empty, `selfcheck` false on every real host; my fixture used a plain directory for `proc/self`, the real-host test did not read `/proc/mounts`) — and found 7 more, **all fixed**:
a. (MEDIUM) `/proc/mounts` → allowlist accepts `/proc/<pid>/mounts`, dead `self/` forms removed, `nfs_mounts` is `unavailable` if unreadable; fixtures use numeric pid directories; **the real-host test now reads `/proc/mounts` and runs `selfcheck` on the real filesystem** (which exposed a second bug: `selfcheck` read `/proc/stat` with a 4 KiB limit → `too_large` on any multi-core host).
b. (MEDIUM) `container_net` held `CAP_SYS_PTRACE`/`CAP_DAC_READ_SEARCH` it does not need (`/proc/<pid>/net/dev` is world-readable with `hidepid=0`; verified on this host) → no capabilities.
c. (LOW-MED) probe answers had no clamp at the wire: a huge integer or NUL/lone surrogate in probe data (sparse files, container labels) turned the whole answer into `FAIL_EXEC` → `sanitize.wire_safe` before canonical encoding.
d. (LOW) Python `splitlines()` splits docker rows on U+0085/U+2028 that Go's `{{json}}` leaves raw → container hidden; → split on `\n` only (test with raw U+0085).
e. (LOW) `activity`, `containers`, `container_net` could exceed `RuntimeMaxSec` (many 15–30 s calls) → deadlines inside the loops, `unparsed`/`skipped: budget` reported.
f. (LOW) trust check skipped the directory holding a symlinked PATH hit (`/usr/local/bin` can be `root:staff 2775` on Debian) → every link on the way, in a trusted directory chain; exec stays on the unresolved path because multi-call programs (`iptables` → `xtables-nft-multi`) choose their function from `argv[0]`.
g. (LOW) `InaccessiblePaths` listed only privd and Docker → also containerd, D-Bus, systemd's private socket, libvirt (except `vms`).
h. (LOW) redacted dict keys could collide and silently overwrite each other (`hf_…` keys) → collisions get `#n`; the unsigned `policy_serial_latest` could grow `_fetched` without bound → capped at 32; `protocol.verify_lease/verify_job/open_envelope` (N1) kept a PATH-resolved default `ssh-keygen` → now **required** (the N1 test call sites were updated mechanically, behaviour unchanged).

4. `nvidia-smi` process names could carry arguments (`python3 --token=…`) → first word, basename only.

## Deviations / decisions
- **The design had no acceptance list for N2** (only §16.1 for N1): derived and added as §16.2; named tests that §16 assigns to privd (`test_blackout_window_berlin_dst`, `test_sunday_before_06`, …) are implemented for the T0 layer under their own names; N3 adds the privd ones.
- **No agent audit file in N2** (`audit.jsonl`, chain, `audit_heads` in poll is `{}`) — gate D / N3, see above. T0 results are not individually chained on the node in N2.
- **Policy installation is not in N2** (privd `policy.apply`, N3). The agent reads the *installed* policy directory (`policy-<serial>.json` + `.sig`, root-owned, as privd will write it — my reading of §7.3/§13.C, to be confirmed by N3), re-verifies it, and **stages** newer hub-delivered policies in `<state>/staging` after verifying their signature; staging activates nothing.
- **Root-only sections are `unavailable` until privd exists**: the agent's `SocketProbeClient` finds no socket. The wire contract and the 12 probe programs are complete and tested with a fake privd; N3 plugs `wire.handle_request` into `gate()`.
- **Hardening tables are data**: names/values verified offline, behaviour unvalidated until `doctor` runs each op's `--selfcheck` in the real unit. Design deviations: agent `AF_NETLINK`; the single `ro-probe` class became a base plus a row per probe (capability split above); the design's class text names only `DAC_READ_SEARCH`/`SYS_PTRACE` but `iptables -S` needs `CAP_NET_ADMIN` — a design gap, now explicit in its own probe.
- **SMART** reported `unavailable` even where `smartctl`/`nvme` exist (needs `CAP_SYS_RAWIO`/`CAP_SYS_ADMIN`, which probes must not get). Design 4.1 said "only if present"; revisit when a host has the tools.
- **Rate buckets per op** (design 9.2 "per op"); the agent's buckets are advisory, privd's (N3) authoritative; persisted in `<state>/ratelimit.json`. The continuous sampling has its own bucket (`metrics.collect`).
- **Unit network bytes need systemd IP accounting** (`IPAccounting=yes`), which forge-node does not switch on (a unit change is out of N2). Units without it report `no counters`; containers in the host network namespace report `not separable`. Container bytes come from `/proc/<pid>/net/dev` of the cgroup's first process (world-readable; heuristic host-namespace detection by host-only `docker*`/`br-*`/`veth*` interfaces). This is the Betriebsleiter-visible limit of §4.1/§14.1 "network bytes per unit"; the design text (§4.1 refinement 8) says so.
- `inv.certs` live handshake covers fixed local ports 443/8443 only (policy has no port field); hub certificate expiry comes from the pinned connection's DER (`T0Engine(hub_cert_der=…)`).
- `PolicyView` ignores policy fields it does not use (full schema validation is the N3 installer); it **does** reject any policy that enables a gated feature.
- Docstrings/comments in the new modules are English (owner principle); N1 modules are German.
- `scripts/run-tests.sh`: test tmpfs is `exec` (fake binaries in the runner tests; container is `--network none`, throw-away), `PYTHONPATH=/w/scripts`, optional `FN_COV`.
- The hub image copies the whole package (it now contains the unused agent/t0 code; the hub imports `t0.params` only).

## Known residuals (recorded for N3/N4)
- (the git-config race residual of the first delivery is gone: git no longer reads the repository's config, see Rework round 1)
- A clock that was once set far into the future parks the rate bucket's saved timestamp there (the limiter never moves it backwards, by design): T0 reads of that op stay rate-limited until real time catches up or `<state>/ratelimit.json` is removed - fail-closed.
