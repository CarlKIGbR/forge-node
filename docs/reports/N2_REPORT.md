## Standards applied
- **One guarded path without optional guard inputs.** Every read goes `agent loop → T0Engine.execute | T0Engine.sample → (collect | probe) → sanitize.finalize`; the probes are reachable only through `wire.handle_request`/`probe_main` → `probes.run_probe`, which re-applies the blackout window itself. Limiter, probe transport, environment, spool, hub-cert provider, pins, `owner_uid`, `expect_uid`, `ssh_keygen`, clock are **required** arguments; `execute(op, tier, params)` has no flags. Pinned by `test_no_function_in_the_t0_layer_or_agent_has_an_optional_guard_input` (AST scan: no guard-named parameter has a default; it caught `_PinnedConnection(pins=())` while writing, and the **independent review** found the sampler as a second read path — now `T0Engine.sample`, only the engine calls `take_sample`: `test_sampling_goes_through_the_engine_guards`), `test_engine_requires_its_guards_as_arguments`.
- **Evidence re-observed before irreversible/trusting decisions:** policy file mode/owner/nlink on the *open descriptor* at every load, the policy directory, `allowed_signers` (also part of the reload cache key); the command binary, **every program it starts and every directory above them** on **each** `run()`; the privd peer uid via `SO_PEERCRED` on every connection **before** sending; the hub leaf pin on every new connection **before** the first request byte; the blackout window inside the probe at execution; the repository's `.git/config` before git runs and **again after** (result discarded if it changed) and the `.git` layout (`commondir`) right before the run; spool segments `lstat`-ed (regular, our uid, one link, expected name) immediately before they are unlinked; a new policy is signature-verified at the moment it replaces the old one and any failure means *no* policy (never the older file); symlinked reads are resolved and the *resolved* target is checked again, then opened without following links.

## Deviations / decisions
- **The design had no acceptance list for N2** (only §16.1 for N1): derived and added as §16.2; named tests that §16 assigns to privd (`test_blackout_window_berlin_dst`, `test_sunday_before_06`, …) are implemented for the T0 layer under their own names; N3 adds the privd ones.
- **No agent audit file in N2** (`audit.jsonl`, chain, `audit_heads` in poll is `{}`) — gate D / N3, see above. T0 results are not individually chained on the node in N2.
- **Policy installation is not in N2** (privd `policy.apply`, N3). The agent reads the *installed* policy directory (`policy-<serial>.json` + `.sig`, root-owned, as privd will write it — my reading of §7.3/§13.C, to be confirmed by N3), re-verifies it, and **stages** newer hub-delivered policies in `<state>/staging` after verifying their signature; staging activates nothing.
- **Root-only sections are `unavailable` until privd exists**: the agent's `SocketProbeClient` finds no socket. The wire contract and the 12 probe programs are complete and tested with a fake privd; N3 plugs `wire.handle_request` into `gate()`.
- **Hardening tables are data**: names/values verified offline, behaviour unvalidated until `doctor` runs each op's `--selfcheck` in the real unit. Design deviations: agent `AF_NETLINK`; the single `ro-probe` class became a base plus a row per probe (capability split above); the design's class text names only `DAC_READ_SEARCH`/`SYS_PTRACE` but `iptables -S` needs `CAP_NET_ADMIN` — a design gap, now explicit in its own probe.
- **SMART** reported `unavailable` even where `smartctl`/`nvme` exist (needs `CAP_SYS_RAWIO`/`CAP_SYS_ADMIN`, which probes must not get). Design 4.1 said "only if present"; revisit when a host has the tools.
- **Rate buckets per op** (design 9.2 "per op"); the agent's buckets are advisory, privd's (N3) authoritative; persisted in `<state>/ratelimit.json`. The continuous sampling has its own bucket (`metrics.collect`).
- `inv.certs` live handshake covers fixed local ports 443/8443 only (policy has no port field); hub certificate expiry comes from the pinned connection's DER (`T0Engine(hub_cert_der=…)`).
- `PolicyView` ignores policy fields it does not use (full schema validation is the N3 installer); it **does** reject any policy that enables a gated feature.
- Docstrings/comments in the new modules are English (owner principle); N1 modules are German.
- `scripts/run-tests.sh`: test tmpfs is `exec` (fake binaries in the runner tests; container is `--network none`, throw-away), `PYTHONPATH=/w/scripts`, optional `FN_COV`.
- The hub image copies the whole package (it now contains the unused agent/t0 code; the hub imports `t0.params` only).

## Known residuals (recorded for N3/N4)
- A repository's owner can still race the git-config scan (`.git/config` rewritten between scan and exec); bounded by the command-line overrides, the explicit git/common dir, the post-run recheck and the probe unit (no network, no write paths, `NoNewPrivileges`, minimal caps, no Docker/privd socket).
- Jobs run inline in the poll thread (no polling while a job runs); worst case ≈ 4.5 min between heartbeats.
- Rate limiting of root probes is authoritative only once privd exists; the hardening sets need `doctor`.
