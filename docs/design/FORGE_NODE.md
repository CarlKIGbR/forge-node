## 0. Summary of the design

1. **Pull, not push.** `forge-node-agent` on each server opens an **outbound mTLS** connection to the hub `forge-nodehub` on carlgpu2 (`192.168.10.4:8094`, LAN only). No new inbound port on carlgpu1/3/4, no sshd change, no firewall change on them. No internet path in either direction (§5).
2. **The node trusts the owner's key, not the hub.** Allowlists are a **signed policy** (`ssh-keygen -Y`, owner key). The policy also lists the hub's signing keys and TLS leaf pin, so a stolen hub credential is revocable by policy (§5.3, §7).
3. **Two processes, one root boundary.** The unprivileged **agent** (T0 reads, relay, no `sudo`, `NoNewPrivileges=yes`) talks over a Unix socket to the root **`forge-node-privd`**. Every mutating or privileged operation enters through `privd` **only**, and `privd` re-runs the *complete* safety pipeline from root-protected state — it trusts neither the agent nor the sudo layer (there is none). Each op then runs in its own **transient systemd unit** with fixed, per-op writable paths (§3.3, §4.4).
4. **Hub-signed jobs and leases.** Jobs and the STOP/freshness lease are signed by a hub gate key listed in the owner-signed policy; a compromised agent can neither originate jobs nor fake "not stopped" (§3.4).
5. **Four tiers.** T0 read · T1 forge-owned management · T2 narrow privileged ops from a compiled-in op table (no wildcard, no free-form target) · T3 owner approval via **typed target manifests**; opaque argv only with explicit double acknowledgement and never on the `t0` profile (§4).
6. **Deny by default, protected set first.** KMU frozen areas (`/opt/kmu-ai`, `/srv/models` **entirely**, `/srv/kmu-ai`), carlgpu4 and everything in the protected set are evaluated before any allow rule; changes need an owner-signed `frozen_ack` (§10).
7. **Forge storage lives on the system disk, bounded by the kernel:** fully allocated loop-ext4 volumes per node and per workload, read-only container roots, sized tmpfs and Docker log rotation; workload-start ops stay disabled until those limits exist; nothing is written to `/srv/models` (§4.2.1).
8. **Exactly-once effects:** durable execution ledger with atomic claims, persisted worker identity and a fence; reconciliation never runs against a live worker, kills and confirms the worker dead and lets delegated effects settle before it probes; indeterminate outcomes block the target and escalate (§9.4).
9. **Audit** on three independent paths (agent log, root-written privileged log, Postgres): one serialized writer per log, root-owned directories and locks, rotation without a writable window, durable intent before action, recovery records instead of rewrites (§8).
10. **Kill switch** first-class: `control/STOP` → signed lease → `privd`; `LOCAL_STOP`; staleness fail-closed; T0 keeps working (§9.1).
11. **Package management is report-only:** no apt apply exists in code, policy schema or units in this revision; `unattended-upgrades` (security only) stays (§4.3).
12. **Honest residual risk:** on carlgpu2 the executor user `forge` is in the `docker` group (root-equivalent, ADR-008); the tiers there bound the planner→node path, not that account (§12).

## 1. Goals, non-goals, constraints

**Goals**
- Give the Betriebsleiter (and through it the graph) *operational eyes and hands* on all four servers: inventory, metrics, logs, start/stop of forge-owned things, a short list of privileged maintenance operations.
- Replace the ad-hoc owner-installed pieces over time: the `state_get` host collector (M-85d), the planned F7 "sudoers drop-in for scene switches", repeated manual Inventur dumps.
- Every action attributable (who asked, which run, which policy), reversible or at least bounded, stoppable within seconds.

**Non-goals**
- No general remote shell, no `docker exec`, no arbitrary file read/write, no arbitrary `systemctl`.
- No orchestration/scheduling of workloads (that stays Compose per host, k3s later — ADR-001).
- No management of KMU services, Tradebot, SecMPro, nexus. They are *observed* (T0, metadata) and otherwise out of scope until the owner signs otherwise.
- No new secrets store. Keys are owner-generated (§6); forge-node never stores provider keys.
- Not a replacement for `grant_worker_host.sh` (F6 worker lanes: SSH key for project executors on g3/g4). Different purpose, different user, different key; they must never share either.

**Constraints taken from the inventory (28.10.) and live checks (31.10.)**
- Heterogeneous hosts: Ubuntu 24.04 (g1–g3) vs **26.04 (g4)**; Python 3.12 vs **3.14.4 (g4)**; node 18 on g2/g3; **`pip`/`uv` missing** on most hosts; Docker 29.2–29.8; docker GID 984 vs 995 (g4). → agent is **stdlib-only Python** shipped as one zipapp; no `pip install`, no package install at all.
- sshd `AllowUsers` differs per host (g2: only `carl`; g4: `tbpost@10.200.0.2`, `carl`, drop-in `60-tradebot-tbpost.conf`) and "on g4 touch nothing". → no ssh-based channel.
- Firewalls: g1 ufw active default-deny; g2/g3/g4 ufw inactive/INPUT ACCEPT; Docker publishes bypass ufw. → agent opens no listener.
- Routing: two /29 subnets, gateways 192.168.10.1 and 192.168.30.1. 30.x→10.3 is proven (NFS 2049, Redis 6379). **30.x→192.168.10.4:8094 is not proven** (router firewall not inventoried) → pre-flight test (§13).
- carlgpu2 live facts: `unattended-upgrades` **enabled** (`20auto-upgrades`), NTP synchronized, TZ Europe/Berlin, ext4 everywhere (so `chattr +a` works), no `smartctl`/`nvme-cli`/`virsh`/`needrestart`, `nvidia-smi` present, **no container carries a `forge.*` label today** (only one sandbox PG has `forge.sandbox_pg=1`), plus leftover test containers (`f5c-review2-*-pg`, `f5brecheck-*-pg`).
- The executor unit (`forge-postbote`) has `NoNewPrivileges`, so `sudo` inside it is impossible. forge-node therefore does **not** use `sudo` at all: the unprivileged agent also runs with `NoNewPrivileges=yes`, and the only root entry is the socket-activated `privd` (§3.3, §4.4).
- Second SSD: on **every** server the second NVMe is KMU storage (g1 `/srv/kmu-ai`, g2/g3/g4 `/srv/models`, M-99). **Decided (OQ-1):** forge data never goes there; the Fabrik uses the system disk (`/srv/forge` on g2, ≈1.2 TB free) with quotas until R1.

## 2. Alternatives and decision

| Criterion | **forge-node (pull agent + signed policy + root `privd` → fixed op scripts)** | Ansible + SSH, restricted keys | SaltStack | Plain SSH forced-commands |
|---|---|---|---|---|
| Inbound ports / sshd changes on KMU/Trading hosts | **none** (outbound only) | sshd `AllowUsers` + keys on all four (g2/g4 differ; g4 "touch nothing") | master↔minion 4505/4506 inbound to master; minion daemon on every host | sshd + `authorized_keys` on all four |
| What a stolen central credential gives | hub cert ⇒ only ops allowed by the *node-local signed* policy, inside windows/rate limits, all audited by root-written log | SSH client key on carlgpu2 ⇒ every forced command / every playbook task, **no** central rate limit, STOP or audit unless re-implemented per host | Salt master compromise = root on all minions (the "unrestricted root" we exclude) | same as Ansible: key on carlgpu2 = all commands, any time |
| Per-call policy (params, windows, plan-hash) | native | per-playbook, bypassed by any ad-hoc `ansible -m shell`; restricted keys limit *commands*, not *policy* | pillar/ACLs possible but coarse (`client_acl`, `peer`), fragile | in a wrapper script per host, duplicated |
| Kill switch / STOP integration | hub + node-local + staleness fail-closed | external (wrap playbook runs) | external | external |
| Audit | hash-chained agent log + root priv log + Postgres | controller log only (target side: sshd/sudo logs) | master job cache; returners | sshd log + wrapper log |
| New software on frozen hosts | one stdlib zipapp + `privd` + fixed op scripts (g1/g4: read-only probes only); no sudo rule, no package install | Python on target (present) + Ansible on controller; modules write temp files, `become` | **salt-minion + deps** (pip-free? no — package/venv), big surface | none |
| Dry-run / plan-hash | designed in | `--check` is best-effort per module | `test=True` best-effort | none |
| Offline/hub-down behaviour | fail-closed, T0 spool | n/a (push) | minion keeps running, may apply cached states | n/a |
| Cost | **we write and maintain ~2–3 kLOC** (agent+hub+scripts) and must test the `privd` gate, ledger and lint surface | low | medium–high (ops of a master) | very low |

**Decision: forge-node**, because the three properties that matter most here — *no inbound surface on KMU/Trading hosts*, *authorization that lives on the node and not in a central secret*, *uniform audit + STOP + rate-limit* — are exactly what the three alternatives cannot give without rebuilding the same agent logic around them. Salt is rejected outright (master = root everywhere). Ansible/SSH-forced-commands remain valid **tools for the owner** (e.g. ad-hoc owner maintenance) but not as the channel the LLM-driven system uses.
**Honest counter-argument and tripwire:** if the op set stayed "T0 read only" forever, hub-held SSH forced-commands would be cheaper and adequate. The decision is justified by T1/T2. Tripwire: if after round 0 + 3 months nobody has requested a T1/T2 op, freeze at T0 and do not build N5–N7 (§15).

Python's standard library has **no asymmetric signature verification**. All signature checks (policy, releases, T3 approvals, hub-signed jobs and leases) therefore call `ssh-keygen -Y verify` (OpenSSH is present on all four hosts because sshd runs) with distinct namespaces: `forge-node-policy`, `forge-node-release`, `forge-node-approval`, `forge-node-hub`. A signature made for one namespace is never valid for another.

### 3.2 Protocol (HTTPS, TLS 1.3 only, HTTP/1.1, JSON, bodies ≤ 1 MiB)

- `POST /v1/poll` (long-poll ≤ 30 s) → `{lease, jobs[≤1], reconcile[], policy_serial_latest}`. It doubles as heartbeat: the agent reports version, policy serial+hash, clock, spool depth, audit heads `seq/hash` per log, and `open_jobs[{job_id, state, attempt}]` from the ledger (read through `privd status`).
- **Lease** (hub-signed, per node): `{node, seq, issued_at, valid_until (≤ 60 s), stop, stopped_projects[], quarantine}`. `seq` strictly increases; `privd` accepts only a newer `seq` and only before `valid_until`.
- **Job** (hub-signed): `{job_id, delivery_seq, node, tier, op, params, dry_run, plan_hash?, requester{identity, planner_call_id, run_id, project}, issued_at, expires_at (≤ 120 s), owner_sig?}`. `job_id` is the idempotency key (graph effect key, §9.4); `delivery_seq` increments per re-delivery of the same `job_id`.
- `POST /v1/jobs/{job_id}/result` · `POST /v1/audit` (batch, ack of highest `seq` per log) · `GET /v1/policy/{serial}` (signed blob; verification is the node's job) · `GET /v1/release/{ver}` (signed artifact; installation still needs the owner, §13).
- Result: `{job_id, attempt, status ∈ committed|dry_run|denied|failed|aborted_safe|indeterminate, reason_code, output(redacted, ≤ 64 KiB), audit_seq_range, plan_hash?}`.
- Reason codes: `DENY_STOP, DENY_LOCAL_STOP, DENY_QUARANTINE, DENY_STALE_LEASE, DENY_CLOCK, DENY_AUDIT_DOWN, DENY_JOB_SIGNATURE, DENY_JOB_EXPIRED, DENY_POLICY_INVALID, DENY_TIER_DISABLED, DENY_OP_UNKNOWN, DENY_OP_MODE, DENY_PARAM, DENY_PROTECTED, DENY_NOT_ALLOWLISTED, DENY_WINDOW, DENY_RATE, DENY_CIRCUIT_OPEN, DENY_STALE_PLAN, DENY_NEEDS_OWNER_SIG, DENY_TARGET_LOCKED, DENY_QUOTA, FAIL_PRECHECK, FAIL_EXEC, FAIL_POSTCHECK, INDETERMINATE`. **Retryable denials** (a later delivery of the same `job_id` may succeed): `STOP, LOCAL_STOP, QUARANTINE, STALE_LEASE, CLOCK, AUDIT_DOWN, WINDOW, RATE, CIRCUIT_OPEN, TARGET_LOCKED`; all others are terminal for that `job_id`.

### 3.3 `privd` — one root entry point, full pipeline

`privd` accepts connections only from `uid forgenode` or `uid 0` (`SO_PEERCRED`; socket mode 0660 `root:forgenode`). Its request set is closed: `exec`, `lease.put`, `t0`, `status`, `selfcheck` (read-only; runs an op's `--selfcheck` in its real unit), `reconcile`, `policy.apply` (root caller or agent with owner-signed blob), `audit.rotate` (root), `lockdown` (root). **Everything the agent sends is untrusted input**; the agent's own pre-checks are advisory (early denial, nicer messages). The authoritative pipeline runs inside `privd`, in this fixed order; each step that denies writes an audit record (and a ledger denial row) and nothing later runs:

1 caller uid → 2 **job signature** (hub gate key from policy, namespace `forge-node-hub`), `node` match, `issued_at ≤ now ≤ expires_at`, ledger claim/lookup (§9.4) → 3 **lease** valid (`valid_until`, `seq` monotonic) and `stop=false`, project not in `stopped_projects`, `quarantine=false` → 4 **`LOCAL_STOP`** file (`/etc/forge-node/LOCAL_STOP`, root-owned) absent → 5 clock skew vs lease `issued_at` ≤ 60 s → 6 audit writable and **intent record fsynced** (mutating ops) → 7 policy valid, serial current, tier enabled, op in the profile's op table → 8 `global_mode`/op `mode` (`observe` or `dry_run_only` ⇒ forced dry-run) → 9 parameter schema → 10 **protected set** on *resolved* objects (for units: the full systemd transaction, §4.3.1) → 11 allowlist match → 12 window → 13 rate buckets and circuit breakers (ledger tables) → 14 `requires: owner_signature` ⇒ valid owner signature over this job → 15 plan hash (dry-run produces and stores the plan; apply recomputes) and quota (`max_bytes`, `min_free_bytes`) → 16 target lock → 17 ledger `started` with worker unit, fence and intent (§9.4) → 18 effect in the op's transient unit → 19 post-check → 20 ledger commit + result audit.

Every op entry in the op table is dispatched by `privd`'s single `gate()` function; there is no code path from the socket to an op script that skips it (a static test enumerates the op table and asserts this). `t0` reads that need root (`t0-probe`, `t0-journal`) go through the same function with a reduced pipeline (steps 1, 2, 5, 7, 9–11 and the light T0 bucket of 13; the lease is checked for authenticity only, its `stop` flag is deliberately ignored for T0) — they never mutate and are allowed during STOP.

**Transport hardening (rev 6, review).** The whole request line must arrive within 10 s of the connection (not per `recv`: one byte every 9 s used to hold a slot for ever); a reply that is not read is abandoned after 10 s; connection slots are split into 24 for the agent uid and 8 only root can use, so a flooded socket still takes root's `lockdown`, `policy.apply` and `reconcile`; the rate buckets of `selfcheck`, `reconcile` and `policy.apply` are per caller uid, so the agent's junk requests cannot use up root's budget. The code between the socket and the nine handlers (`dispatch`, `serve_connection`, `serve`) has no effect of its own — a static test asserts it. The one transition `received → started` of the ledger also checks the target lock and "one mutating op per node" **in the same transaction** (steps 16/17 are an early exit plus the authoritative check), so two jobs cannot both pass and both start. `fresh evidence` before the irreversible unit start covers LOCAL_STOP, the lease re-verified under the *current* policy's gate keys, and the installed policy itself (a revocation, a disabled op or tier, a new protected entry, a new blocking mode, the blackout window).

### 3.4 Why hub-signed jobs and leases

Without them a compromised agent (uid `forgenode`) could call `privd` directly and exercise every allowed op at will, bounded only by rate limits. With them it can only (a) replay nothing (claims, expiry), (b) withhold or delay (⇒ stale lease ⇒ fail-closed), (c) read what T0 returns. A compromised **hub** can still issue any job inside the node-local policy, windows, rate limits and `owner_signature` requirements; stealing the hub gate key is the residual hub risk (revocation: §5.3). The lease is verified by `privd` itself — the agent merely carries it — so "STOP knowledge" is never an agent claim.

### 3.5 Decision pipeline summary (hub side, before signing)

Hub authz (identity/project/tier matrix, §11) → hub-side STOP check under `.dispatch.lock` → quota/rate mirror → sign job. The hub's checks are a first line; the node never relies on them.

(2) `ss -p`, `iptables`, `docker`, `sshd -T`, `journalctl`, git/model/cert reads of other users' files run in `ro-probe` units (`forge_node.t0.probes`); the agent degrades each section to `unavailable` when `privd` is unreachable. (3) SMART is reported `unavailable` in N2 even where `smartctl`/`nvme` exist: collecting it needs `CAP_SYS_RAWIO`/`CAP_SYS_ADMIN`, which the `ro-probe` class does not get. (4) Rate buckets (light ≤ 2/min, heavy ≤ 1/10 min) are per op. (5) Git: revision and branch are read from `.git/HEAD`/refs without executing git. The tracked-dirty count runs `git status` against a **private snapshot git directory generated by the probe** (HEAD, the ref it read, an empty `objects/`, and a config the probe writes from validated inert `core.*` switches such as `filemode`, `autocrlf`, `ignorecase`); the repository contributes only data (`GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, work tree) and git never opens its own config, hooks, `commondir`, `config.worktree`, `info/attributes` filter definitions or submodule configs (`--ignore-submodules=all`). There is no scan-then-run and no recheck: replacing `.git/config` before, at or after the probe reads it changes nothing. The branch name comes from the repository's owner and is checked with git's ref-format rules on a stricter charset (no leading `/` or `-`, no `//`, `..`, `.lock`, empty or dot-leading components, no NUL/backslash/space/control characters); a HEAD that names anything else is rejected (`malformed_ref`, git is not started), and every file of the snapshot is created through a directory descriptor with validated components, `O_NOFOLLOW`/`O_EXCL` (`t0/confined.py`) - the same helper writes the agent's staged policy blobs. Anything not carried over is listed as `config_not_used` (e.g. `filter.lfs`: the count is then computed without filters). (6) Symlinks are normal on real hosts (`/etc/os-release`, `/proc/net`, `/var/run`, `/sys/class/*`): an allowlisted path may be a link, but its resolved target must be allowlisted too (live proof: refusing links made `inv.host` `ok` but empty). (8) `inv.usage` network bytes per container/unit over the window come from per-sample counters: containers via `cgroup.procs` → `/proc/<pid>/net/dev` (world-readable, no privilege; containers in the host network namespace are detected by the host-only bridge/veth interfaces and reported as `not separable`, no counters), units only where systemd IP accounting is already on (`IPIngressBytes`/`IPEgressBytes`; forge-node does not switch it on - that would be a unit change); counter resets (recreated container, restarted unit) count from zero. Units without accounting report `no counters`. (9) Everything the sampler persists passes the same filter as the outgoing envelope (`sanitize.protect`), and redaction is key-aware (`api_key`, `token`, `secret`, `password`, … also as dotted label keys such as `forge.api_key`). (7) The `ro-probe` class is a base plus a row per probe: `net` (`ss -p`, `CAP_SYS_PTRACE`) and `firewall` (`iptables -S`, `CAP_NET_ADMIN`) are separate probes, `container_net` (per-container `/proc/<pid>/net/dev`, `CAP_SYS_PTRACE`) is separate from the `containers` inventory, probes that do not inventory containers cannot reach Docker's or privd's socket (`InaccessiblePaths`); table in `forge_node/t0/hardening.py`. Logs of `kmu-*` and anything on g4 are **not allowlisted by default**; if the owner adds them they carry `sensitivity: customer` and the existing `effective_sensitivity`/`model_policy` guard (M-84) withholds them from non-permitted models.

### 4.2 T1 — forge-owned management

Authority comes from **ownership markers**, not names:

- **Containers:** only those with label `forge.managed=true` **and** `forge.node=<this node id>`; `forge.project=<slug>`, `forge.stack=<name>`; `forge.critical=true` excludes from T1 (postgres, litellm, edge, hub: stopping them kills audit/inbox → T2-allowlisted restart or T3). Labels are immutable after creation, so a non-forge container cannot acquire them. **Today no container has these labels** → the first implementation slice adds them to forge-core/fundament/edge compose files (applied at the next recreate, outside the window); the leftover test containers get labels or are removed by the owner (T3 manifest `container_action`).
- **Ops:** `container.start|stop|restart|recreate <id>` (acts on the full container ID resolved from the name *after* the label check — no TOCTOU), `stack.put|up|down`, `volume.create|grow|destroy`, `dir.*`, `file.put|get`, `vm.*`.
- **Stack bundles** (new definitions) are the dangerous part: `docker` = root. Therefore:
  1. `stack.put` stores `compose.yaml` under `<forge_root>/stacks/<stack>/` (hash recorded).
  2. The op runs **`docker compose config --format json`** (creates nothing), lints the *resolved* model — `extends`, `include`, interpolation and anchors are already expanded — and **applies the rendered model, not the YAML**.
  3. Lint is an **allowlist of keys**: unknown keys ⇒ reject. Required: image by `@sha256:` digest (no floating tags, ADR-008), local image only (`pull` disabled), `forge.*` labels, non-root `user` unless policy allows, `no-new-privileges`, `mem_limit`/`cpus`/`pids_limit`, `restart: no|on-failure`, healthcheck, **and the write-path rules of §4.2.1**. Forbidden: `privileged`, `cap_add` (except a policy list, default empty), `network_mode: host`, `pid|ipc: host`, `devices` (GPU only via `deploy.resources.reservations.devices` within the policy `vram_budget_mib`), `docker.sock`, any mount whose **realpath** lies in the protected set or outside the stack's own volume, ports on `0.0.0.0`, reserved ports (§12 of the ADR doc + inventory §2), networks other than new `forge_*` networks inside `172.28.0.0/16` (never touch `daemon.json`).
  4. `stack.up` = `docker compose -p forge-<stack> up -d` on the rendered file; project namespace `forge-<stack>` prevents collisions with KMU compose projects.

#### 4.2.1 Storage: every write path of a running workload has an enforceable limit (OQ-1)

**Decision (OQ-1, fixed):** forge data never goes to `/srv/models`, `/srv/kmu-ai` or any KMU mount; the Fabrik uses the **system disk**. The first revision accounted bytes before/after ops and while `privd` writes — that cannot bound what a *running* container or VM writes afterwards. The design therefore replaces accounting by **kernel-enforced allocations**, and where a path cannot be bounded yet, the op that would start such a workload **stays disabled**.

**Mechanism (chosen).** Project quotas are not available: ext4 `prjquota` needs the `project` feature enabled with `tune2fs` on an *unmounted* filesystem (not possible for the live root fs) and there is no XFS or LVM on these hosts. So limits come from **loop-mounted ext4 images whose backing files live on the root filesystem and are fully allocated up front** (`fallocate`, so the space is reserved at creation and a full workload cannot take more from the system disk):
1. **Forge root volume** per node (`forge_roots[]`, e.g. g2 `/srv/forge/node`, 100 GiB initially): the aggregate bound for everything forge puts on this node. Backing file `/var/lib/forge-node-img/forge-root.img` (root 0600, on `/`, never on a protected mount), mounted `nodev,nosuid` by a systemd mount unit created in the install (§13.C C3).
2. **Per-workload volumes** (`volume.create {stack|vm, size}`, T1 op): one ext4 image per stack or VM *inside* the forge root volume, mounted at `<forge_root>/mnt/<name>` (`nodev,nosuid`), registered in `/var/lib/forge-node-priv/volumes.json`; `forge-node-volumes.service` (root oneshot, `After=` the forge root mount) re-mounts the registry at boot. **Unmounted-mountpoint guard:** every mountpoint directory (the forge root and each `mnt/<name>`) is `chattr +i` while unmounted, so nothing can ever be written into the empty directory on the system disk if a mount is missing; and lint accepts only `restart: no|on-failure` (never `always`/`unless-stopped`) — after a reboot the hub re-issues start jobs once `doctor`/`privd status` confirm the volumes are mounted, so Docker cannot start a stack before its volume exists. `volume.grow` is online (`truncate`/`fallocate` + `losetup -c` + `resize2fs`) and bounded by the free space of the forge root volume; shrink never. `volume.destroy` requires the stack to be down and moves the image to `.trash`.
3. A workload that writes more than its volume gets **`ENOSPC` from the kernel at its own allocation** — no node job, no `privd` involvement, and the system disk is unaffected beyond the space reserved at creation.

**Every write path, and how it is bounded:**

| Write path | Limit | Enforced by | Required in lint / policy |
|---|---|---|---|
| Bind-mounted data | the workload's volume (ext4 loop image of fixed size) | kernel `ENOSPC` | every writable mount must be a bind from `<forge_root>/mnt/<stack>/…` |
| Container writable layer (`/var/lib/docker/overlay2`, **system disk, ext4 without storage-opt support**) | **zero by construction** | `read_only: true` root filesystem | `read_only: true` mandatory; writable scratch only via tmpfs or volume |
| tmpfs | `size=` bound, charged to the container memory limit | kernel + cgroup | every tmpfs needs `size`; counted inside `mem_limit` |
| Anonymous volumes (image `VOLUME` declarations create them in `/var/lib/docker/volumes`) | none unless mounted over | lint | `docker image inspect` `Config.Volumes` of every image is read; each declared path must be explicitly mounted (volume bind or tmpfs) or the stack is rejected; named volumes forbidden |
| Container logs (`json-file` in `/var/lib/docker/containers`, system disk) | `max-size × max-file` per service | Docker log rotation | `logging: {driver: json-file, options: {max-size, max-file}}` mandatory, `max-size ≤ 10m`, `max-file ≤ 3`; policy `log_budget_bytes` limits the sum over all stacks (checked at `stack.up`) |
| VM disks (qcow2) | qcow2 virtual size ≤ volume size; physical growth bounded by the volume; `preallocation=falloc` where size matters | kernel `ENOSPC` inside the volume + libvirt | domain XML lint: disks only inside the VM's volume; no `<filesystem>` passthrough |
| VM logs (`/var/log/libvirt/qemu/forge-*.log`) | **hard-bounded, continuously** (e.g. `virtlogd` `max_size`/`max_backups`); a periodic `logrotate` alone leaves a window and is not sufficient | verified by `doctor` and by the continuous log-flood test | **gate B** — prerequisite for enabling `vm.define|start` |
| Docker build cache / pulled images | none needed: builds and pulls are not forge-node ops; images are loaded by the owner/registry | — | `docker.prune_*` removes only unpinned leftovers (§4.3) |
| node's own state (ledger DB, rotated logs, T0 spool) | terminal ledger rows purged after 90 d; audit files bounded by the ack watermark and the 500 MiB unacked cap (§8.4); spool ring 50 MiB | `privd` / agent | — |

**Per-op status (explicit):**

| Op | Status in the initial policy | Condition to be enabled |
|---|---|---|
| `dir.ensure|du|trash|purge_trash`, `file.put|get` | **disabled until gate D** (every op above T0), then enabled | the forge root volume is mounted (`privd` checks fstype `ext4`, loop device, backing file on `/`, `nodev,nosuid`) — else `DENY_NO_QUOTA_BACKEND` |
| `volume.create|grow|destroy` | **disabled until gate A and gate D** | same; sizes bounded by the free space of the forge root volume; mounts must live in the host mount namespace (gate A) |

| `container.start|restart|recreate`, `stack.up` | **disabled** (`t1.workloads_enabled:false`; gate A and gate D) until slice N5 delivers the lint **and** the node's forge root volume exists and is host-visible; then enabled per stack only when the stack passes the full lint (read-only rootfs, volume-only writes, tmpfs sizes, log options, no anonymous volumes). `DENY_NO_WORKLOAD_LIMITS` otherwise | policy schema rejects `workloads_enabled:true` for a root without `quota_backend:"loop_fs"` |

**Acceptance (all required, run on g2 in N5 — workload acceptance, not part of round 0; gate A):** (a) a running selftest workload (`selftest.fill`, `full` profile only) bind-mounted to its volume writes until `ENOSPC` — the write fails at the allocation, the system disk's free space does not drop by more than the space reserved at creation, and **no node job is issued** during the test; (b) a log-flooding container stays within `max-size × max-file`; (c) a tmpfs fill stops at `size`; (d) a stack without `read_only`, with an undeclared image `VOLUME`, or with a missing `logging` section is rejected at `stack.put`; (e) with the forge root volume unmounted, `stack.up` and `volume.create` are denied; (f) volumes are re-mounted at boot before any stack starts.

**Directories.** `forge_roots` per host: carlgpu2 `/srv/forge/node` (backing image on `/`, ≈1.2 TB free on 28.10.), carlgpu3 `/var/lib/forge-node/data`, none on carlgpu1/carlgpu4 (T0-only). Policy per root: `{path, quota_backend:"loop_fs", backing_image, size_bytes, log_budget_bytes, min_free_bytes}` — `size_bytes` is the image size (the hard bound); `min_free_bytes` is the free space the *root filesystem* must retain **after** creating or growing the image (checked at create/grow time; afterwards the reservation makes it moot). Ops: `dir.ensure|du|trash|purge_trash`, `file.put|get ≤ 10 MiB`. Implementation requirement (named test): per-component walk with `O_NOFOLLOW|O_DIRECTORY` from a `dirfd`, `st_dev` equal to the forge root volume's device **and different from every protected mount's device**, no `..` escape. Delete = move to `.trash/<date>/`, purged after N days by a separate op with byte/count caps.

- **VMs (ADR-023, F5n):** libvirt pool `forge` as a dir pool inside a VM volume (`<forge_root>/mnt/vm-<name>`); until R1 decides about the second SSD, VM images stay on the system disk (the ROADMAP's "Images auf zweiter SSD" is on hold, M-99). Domains `forge-*` with forge metadata; `vm.define` from a lint-checked template (no hostdev, no host-path filesystem passthrough, disks only in the pool, NAT bridge only). **Disabled until libvirt exists** (not installed on g2); target host for the lab is carlgpu3 after pe_packer M022.
- The agent never needs the `docker` group: T1 docker/libvirt effects run in `privd`-started op units.

### 4.3 T2 — privileged allowlisted operations

T2 ops exist **only as entries of the compiled-in op table** shipped in the signed release (no entry ⇒ no code path). Each entry fixes: op name, script, parameter schema, target class, unit property set (§4.4), idempotency class and probe (§9.4), default rate bucket, `abort_on_stop`. The policy can only *enable/disable* entries and bind them to targets; it cannot add ops.

| Op | What it does | Guards |
|---|---|---|
| `unit.start|stop|restart <unit>` | `systemctl` on **enumerated** units (e.g. `forge-edge.service`, `forge-docker-user.service`) | unit's `FragmentPath` must be `/etc/systemd/system/forge-*` or explicitly listed; the **complete systemd transaction** (forward activation, `Conflicts=` in both directions, stop-closures; §4.3.1) is resolved first and must contain no protected unit, and its `closure_sha256` must match the signed policy; pre-check "checkout = runtime" for units with a `checkout_path` (ADR-012 restart trap); `forge-postbote.service` has mode `graceful_flag` → writes the existing `post/state/restart-requested` flag instead of `systemctl restart` (M-43) |

**Package management is report-only in this revision (OQ-12, decided).** There is **no** `apt.*apply*` op in the op table, none in any profile, no apt window in the policy, and the policy schema **rejects** any op or feature flag named like it (schema validation fails the whole policy, `DENY_POLICY_INVALID`). `unattended-upgrades` (security pocket only) stays as the host's own mechanism; forge-node does **not** disable, reconfigure or race it. What forge-node does: `inv.pkgs` (§4.1) reports installed `unattended-upgrades` status, last run time/result from `/var/log/unattended-upgrades/`, pending security updates (`apt-get -s`, read-only), held packages, `reboot-required`, and **drift** from "security origins only" (`Allowed-Origins` / `Unattended-Upgrade::Package-Blacklist` parsed from `apt-config dump`); drift and failed runs produce inbox findings (`node_alert`). Installing a package or applying updates beyond that remains a T3 manifest (`package_install`, §4.6) signed by the owner.

Policy field per op: `requires: none | owner_signature`. Default `none` for forge-owned restarts; `owner_signature` for any unit outside `forge-*`. Asymmetry principle: ops that *reduce* risk or privilege (stop, pin, deny, quarantine) sit a tier lower than ops that *increase* it.

#### 4.3.1 Systemd transaction resolution (T2 `unit.*` and T3 `unit_action`, **before** authorization)

> **N3 refinement (found by the live check on carlgpu2, rev 6).** Evaluated literally, "any member of F, C or S is protected / uses `OnFailure=`" denies *every* real unit: the forward closure of any service reaches `sysinit.target`, `local-fs.target` and `-.slice` (the first two use `OnFailure=emergency.target`), and even `forge-edge.service` — this section's own example — `Requires=docker.service`. Starting a unit does nothing to a dependency that is already active. The resolver therefore computes the complete closure (all of it enters `closure_sha256`, with every member's fragment, drop-ins and `On*=` data **and the sha256 of the text of everything the transaction changes** — fragment and drop-ins as `systemctl cat` prints them) but evaluates protected-name/path hits, the "no fragment" rule and the gate-C rule on the **effect set**: the requested unit and forward members that are *not active* (they would be started). The relaxation applies to the **start side only**; everything the transaction would **stop** — conflicting units, the stop-closure (`RequiredBy`, `RequisiteOf`, `BoundBy`, `ConsistsOf`, `PropagatesStopTo`), restart/reload propagation, dependencies with `StopWhenUnneeded=yes` — is an effect whatever its state is *now*, because the state can change between the check and the action (the op must re-resolve inside its worker under the effect lock and compare `closure_sha256`: N6). `try-restart` and `reload-or-restart` resolve as a `restart`. `enable`/`disable` read the unit's `[Install]` section (`systemctl cat`): `WantedBy=`/`RequiredBy=`/`UpheldBy=` targets, `Alias=` names and `Also=` units are part of the transaction, and a protected *name* is a hit even when no such unit is loaded. A `.mount`/`.automount` is judged by what it mounts (`Where=` is, lies under or contains a protected path: `srv-models.mount` comes from a generator and matches no name pattern). An inactive protected dependency is a hit. `closure_sha256` has format version 2. Quoted unit names in `systemctl show` output (escaped mount units) are parsed. On carlgpu2 the effect set of every start/restart still contains an inactive oneshot with `OnFailure=` (`systemd-fsck-root.service`), so all unit start/restart operations remain denied there — which is the gate's intent until N6 follows the edges.

> **Gate C (Betriebsleiter decision):** the resolver below does not yet follow `OnSuccess=`/`OnFailure=` edges or isolate job modes. Until it handles them recursively and binds them into `closure_sha256`, it **rejects any unit — or any member of its closure — that uses `OnSuccess=`/`OnFailure=`, or an isolate job mode** (fail-closed, like an incomplete resolution), and all unit ops stay disabled (`forge_node/gates.py`). Tests: see "Gated features".

Starting or restarting a unit does not only touch that unit: systemd builds a transaction that also activates dependencies and **stops units that conflict** (`Conflicts=`, in either direction). A permitted unit with `Conflicts=ollama.service` would stop a protected service. Round 1 only walked the *reverse* closure for stop/restart. The resolver therefore computes the **complete action-specific transaction** from the unit graph and runs it in step 10 of the pipeline (protected set) — for T2 before the allowlist match, for T3 before the `frozen_ack` check:

| Action | Resolved set |
|---|---|
| `start`, `try-restart`, `reload-or-restart` on an inactive unit | **F** = unit ∪ forward activation closure over `Requires=`, `Requisite=`, `BindsTo=`, `Wants=`, `Upholds=` (transitively; `Wants=` members are started too) ∪ units reached through `Triggers=` of sockets/timers (later activation). **C** = every currently loaded unit named in `Conflicts=` of any member of F **or** carrying a `Conflicts=` that names a member of F (`ConflictedBy`). **S** = stop-closure of C (reverse edges: `RequiredBy=`, `BoundBy=`, `ConsistsOf=` and `PropagatesStopTo=`) |
| `stop` | unit ∪ stop-closure (`RequiredBy=`, `BoundBy=`, `ConsistsOf=`, `PropagatesStopTo=`) |
| `restart` | stop set of the unit ∪ **F, C, S** of the start ∪ `PartOf=`/`PropagatesReloadTo=`-propagated restarts |
| `reload` | unit ∪ `ReloadPropagatedTo=` targets |
| `enable`, `disable`, `mask`, `unmask` | the unit, its `WantedBy=`/`RequiredBy=` target units (boot-time effect), and the same stop-closure for `disable`/`mask` of a running unit |

Properties are read with `systemctl show` (including `ConflictedBy`, `RequiredBy`, `BoundBy`, `ConsistsOf`, `Upholds`, `Triggers`, `TriggeredBy`) on the live manager, so drop-ins, templates and generated units are included.

**Protected hit** if **any** member of F, C, S (or the other sets) is in the protected unit set, has a `FragmentPath` in a protected path, or is a template instance/unit the resolver cannot fully enumerate (`systemctl show` error, missing property, unit not loaded but referenced) — **an incomplete resolution is a hit (fail-closed)**. The result records the edge that led to the hit (e.g. `forge-x.service —Conflicts→ ollama.service`).
- **T2:** a hit ⇒ `DENY_PROTECTED` (T2 has no acknowledgement path). In addition the policy target for each enumerated unit and action carries `closure_sha256` = hash of the resolved sets as computed by `privctl unit-closure <unit> <action>` at signing time; a later change (new drop-in, new `Conflicts=`) ⇒ `DENY_CLOSURE_CHANGED` until the owner re-signs.
- **T3:** a hit ⇒ the signed blob must carry `frozen_ack:true` **and** `closure_sha256` (shown to the owner in the dossier as a list of affected units); `privd` recomputes at execution and compares (the unit graph may change between approval and execution) — mismatch ⇒ `DENY_CLOSURE_CHANGED`.
- Wrapper ops that start/stop units internally (`scene.switch` → `kmu-s2-scene`) declare `touches_units[]` in their op-table entry; the resolver runs on each listed unit and action when the policy is applied and again at execution.
- Probes (§9.4) for `unit.*` verify the *intended* effect and additionally compare the active state of all protected units against a snapshot taken before the worker started; any change raises a `node_alert` (detection in addition to prevention).

### 4.4 Privilege boundary: `privd`, op units, no sudo

**Why not sudo.** The first revision ran helpers as `sudo` children of an agent under `ProtectSystem=strict`. Children inherit the mount namespace, so the helpers could not have written policy, privileged state or managed directories, and the agent could not have had `NoNewPrivileges`. Sudo argument matching is also a poor boundary for typed parameters. This revision removes `sudo` from the design: **no sudoers entry exists for `forgenode`** (a test asserts `/etc/sudoers*` contains none). The original intent — *narrow rules to fixed root-owned scripts with parameter validation* — is kept: the "rules" are the op table, the "scripts" are root-owned files in the release tree, and the validation runs in `privd` and again in the script.

**Units.**
- `forge-node-privd.socket`: `ListenStream=/run/forge-node/priv.sock`, `SocketMode=0660`, `SocketUser=root`, `SocketGroup=forgenode`.
- `forge-node-privd.service` (root): `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `ReadWritePaths=/var/lib/forge-node-priv /var/log/forge-node-priv /var/log/forge-node-agent /run/forge-node /etc/forge-node`, `ProtectKernelTunables/Modules=yes`, `RestrictAddressFamilies=AF_UNIX`, `IPAddressDeny=any`, `NoNewPrivileges=yes`. `privd` itself writes only its state, the logs, the installed policy (`/etc/forge-node/policy`) and `/etc/forge-node/LOCAL_STOP` (`lockdown`); a unit can only grant a directory, not a single file, so the grant is `/etc/forge-node` (rev 6 — `allowed_signers` there is root-owned and its mode is re-checked on every use); it performs **no** effect itself.
- **Per-op transient units.** `privd` starts each op as a transient unit named `forge-node-op-<job_id>-<attempt>.service` (`systemd-run --unit … -p …`, **no `--collect`**, so the unit's state stays queryable; `KillMode=control-group`, `SendSIGKILL=yes`, `TimeoutStopSec=30`) using a **property set taken from the op table, never from request parameters**. The worker reports to `privd` only through its per-attempt `status.json` and an inherited pipe (§8.2, §9.4). The sets are classes:

| Class | Used by | Key properties |
|---|---|---|
| `ro-probe` | `t0-probe`, `t0-journal`, `inv.*` privileged parts | `ProtectSystem=strict`, no `ReadWritePaths`, `PrivateTmp`, `CapabilityBoundingSet` minimal (`CAP_DAC_READ_SEARCH`, `CAP_SYS_PTRACE` only where `ss -p` needs it), `IPAddressDeny=any`, `NoNewPrivileges` |

- **Validation inside the real unit.** Every op script has a side-effect-free `--selfcheck` that exercises each path, socket and capability the op needs (open for write where RW is declared, connect to sockets, `stat` targets). `forge-node doctor` runs `selfcheck` for **every enabled op inside its real transient unit** and fails the install step if any is denied; the same runs in the N3 acceptance on carlgpu2. This is the answer to "a hardening profile that silently breaks the op".
- The agent's T0 reads that need root (`t0-probe`, `t0-journal`) use the same mechanism with class `ro-probe`.

`User=forgenode`, **`NoNewPrivileges=yes`** (possible now, no sudo), `ProtectSystem=strict` with `ReadWritePaths=/var/lib/forge-node /var/log/forge-node-agent` (the *directory* is root-owned; file permissions allow only appending to the active agent log, §8.2), `ProtectHome=yes`, `PrivateTmp=yes`, `ProtectKernelTunables/Modules/ControlGroups=yes`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK` (N2: `ss` and `ip route` of `inv.net` use netlink; revision 3 omitted it), `IPAddressDeny=any` + `IPAddressAllow=192.168.10.4/32 127.0.0.0/8` (**egress limited to the hub**), `SystemCallFilter=@system-service`, `CapabilityBoundingSet=` (empty), `LimitFSIZE=134217728` (N3: the agent can append to its own group-writable audit file, so one file is bounded; Python ignores `SIGXFSZ`, the write fails with `EFBIG` and the log is `AuditDown` for the agent), `MemoryMax=128M`, `CPUQuota=15%`, `Nice=19`, `IOWeight=10` (g4: `MemoryMax=96M`; its swap is 1.8/2.0 GiB full), `Restart=on-failure`, `RestartSec=10`. ### 4.6 T3 — everything else → owner approval, via typed manifests

T3 is the explicit fallback for anything not in policy. It starts from a **proposal** and is executed by `privd` (op `t3.exec`) only after an owner signature. The central rule: **`privd` must know what a T3 action touches.** Therefore T3 has a closed catalog of **manifest kinds**; the only escape hatch is an *opaque* command with extra acknowledgements.

**Manifest catalog (each entry: fields → how `privd` resolves affected objects independently of the proposal text):**

| Kind | Fields | Resolved targets (computed by `privd`, not taken from the proposal) |
|---|---|---|
| `unit_action` | `unit`, `action ∈ start|stop|restart|enable|disable|mask|unmask` | unit `Id`, `FragmentPath` (realpath) and the **complete action-specific systemd transaction of §4.3.1** (forward activation, `Conflicts=` both directions, stop-closures, boot-time `WantedBy=` effects) — a protected unit anywhere in it, or an incompletely resolvable edge, is a protected hit; the signed blob binds `closure_sha256` |
| `container_action` | `id`, `action ∈ start|stop|restart|rm` | inspect: labels, compose project, mounts' **source realpaths**, networks, published ports. Any container **without** `forge.managed` counts as a protected hit (foreign) |
| `file_replace` | `path`, `expect_sha256_before`, `content_sha256`, content stored by the hub (≤ 256 KiB, verified against the hash) | realpath of `path` and its parent chain; refuses if the before-hash differs; atomic replace with a backup copy |
| `dir_remove` | `path` | realpath, recursive size and device |
| `package_install` | `packages[]` (explicit names), `plan_hash` from `apt-get -s install` | the **resolved** package set incl. dependencies; docker\*, containerd\*, nvidia\*, libnvidia\*, linux-\*, held packages and anything that restarts a protected unit are protected hits |
| `firewall_apply` | `mode ∈ apply|confirm|remove` | fixed script `forge-docker-user.sh`; no free arguments |
| `policy_replace_trust` | new `allowed_signers` content | key rotation (§6) |

`frozen_ack` rule: **`frozen_ack:true` inside the signed blob is required exactly when `privd`'s own resolution yields at least one protected hit**; if there is a hit and no ack ⇒ `DENY_NEEDS_OWNER_SIG` even with a valid signature. (An ack without a hit is allowed and logged.) The proposal text, the hub's classification and the planner's description are never trusted for this decision. Unknown kinds are rejected.

**Opaque commands.** Anything the catalog cannot express is an *opaque argv*. `privd` cannot determine its effects through scripts, shells or indirect service actions, so it must **assume protected effects**:
- opaque execution is **disabled by default** (`t3.opaque_enabled:false` in policy) and **not installed at all on the `t0` profile** (g1, g4): there, opaque commands are **Mode A only** — the owner runs them by hand;
- where enabled (g2, g3 `full` profile, owner-signed policy), the signed `approval/v1` blob must contain **`opaque_ack:true` and `frozen_ack:true`** and an `exec_spec` with the exact `argv[]` (no shell string), `cwd`, an **empty environment** and `timeout_s`, all covered by `target_sha256`; it runs in the `t3-opaque` unit class, single-use nonce, ≤ 24 h validity, full output into `priv.jsonl`; the Cockpit shows a red "opaque, effects unknown" banner;
- the proposal creator is asked to produce a manifest first; an opaque proposal must state why no manifest kind fits (recorded, reviewed by the Betriebsleiter before it reaches the owner).

**Canonical approval schema `approval/v1`** — one schema for every kind, canonical JSON (keys sorted, UTF-8, no floats), signed with `ssh-keygen -Y sign -n forge-node-approval`:
```json
{"schema":"approval/v1","proposal_id":"…","node":"carlgpu2","kind":"unit_action|container_action|file_replace|dir_remove|package_install|firewall_apply|policy_replace_trust|opaque",
 "target_sha256":"sha256(canonical(manifest))  or  sha256(canonical(exec_spec))",
 "exec_spec":null,  "closure_sha256":null,
 "override_window":false,"frozen_ack":false,"opaque_ack":false,"not_after":"2026-11-01T12:00:00Z","nonce":"…"}
```
For `opaque`, `exec_spec` = `{argv[], cwd, env:{}, timeout_s}` and `target_sha256` covers all of it; for typed kinds `target_sha256` covers the manifest and `closure_sha256` is set for `unit_action`. `override_window`, `frozen_ack`, `opaque_ack`, `not_after` and `nonce` are top-level signed fields. `privd` re-canonicalizes what it is about to run, recomputes the hashes, and refuses anything that differs from the signed values, a non-empty `env`, or flags the resolution does not need/allow.

**Flow** (unchanged intent, now precise):
1. `node_t3_propose(node, kind, manifest | opaque{argv,why}, purpose, risk, rollback, preconditions, postconditions, expires_in)` → hub stores a proposal (`command_text` rendered exactly as it will run, `target_sha256`, T0 precheck results, rollback), writes an **inbox escalation** (`kind=node_action`, ≤ 400-token dossier), calls the extended `approvals_request(kind='node_t3', ref='node-proposal:<uuid>')` (§11) and a push notification.
2. **Mode A "owner executes":** Cockpit shows the copy-paste block, hash, rollback, postconditions; after the owner ran it, the hub runs the postcondition T0 checks and closes the proposal `done`/`postcondition_failed` with evidence.
3. **Mode B "approve once":** owner signs on the Mac (`ssh-keygen -Y sign -n forge-node-approval`) an `approval/v1` blob (above; `not_after ≤ 24 h`); uploaded via Cockpit or `scp`. A Cockpit *click* alone never authorises execution (the browser session lives in the planners' trust zone). `privd` verifies signature, node, expiry, single-use nonce (ledger), re-resolves targets, applies the `frozen_ack` rule and runs it through the full pipeline (STOP/lease/window/ledger apply to T3 too; windows can be overridden only by `override_window:true` in the signed `approval/v1` blob, logged).
4. T3 is never a standing capability: no signed blob ⇒ no root action.

## 5. Transport

### 5.1 Direction and addressing
- Agents dial `https://192.168.10.4:8094`. The hub listens **only** on the carlgpu2 LAN IP (container publish `192.168.10.4:8094`), never `0.0.0.0`; the local node on g2 uses the same address.
- Filter on g2: Docker publishes bypass ufw ⇒ rule in **`DOCKER-USER`** via the existing `forge-docker-user.sh` (extended in a forge-ops slice): allow TCP/8094 from `192.168.10.0/29` and `192.168.30.0/29` only, not from the VPN `10.200.0.0/29`, else DROP — deployed with the script's 5-minute rollback timer (`--confirm`).
- **Routing 192.168.10.x ↔ 192.168.30.x:** router-based (gateways .10.1/.30.1). Evidence of working 30→10: NFS from 10.3 mounted on g3/g4, Redis 6379 allowed from `192.168.30.0/24`. Return path for 10.4→30.x replies is stateful and needs no extra route. **Unproven:** a router/pfSense rule for 30.x→10.4:8094. Pre-flight (§13): hub listener up with a self-test endpoint, then from g3/g4 `openssl s_client -connect 192.168.10.4:8094 -brief </dev/null`. If it fails: owner adds one router rule (TCP 8094, src 192.168.30.0/29, dst 192.168.10.4); nothing else changes.
- **No inbound internet; no outbound internet for the agent** (systemd IP filter, §4.5). The hub has no internet requirement; ntfy/e-mail for push is the existing F5c channel, not forge-node's.
- MTU 1500 assumed; the JSON payloads are small. Clock: node refuses jobs if `|node − hub| > 60 s` (certificate validity and `expires_at` depend on time); NTP sync is part of `inv.host`.

### 5.2 mTLS details
- Private CA (EC P-256, 5 years) created **on the owner's Mac**; the CA key never touches a server. Separate from Caddy's internal CA.
- Node cert: EC P-256 keypair **generated on the node** (`forgenode` 0600), CSR signed by the owner; `CN=forge-node-<id>`, `SAN URI=urn:forge:node:<id>`, EKU `clientAuth`, **90 days**. Hub cert: SAN `IP:192.168.10.4`, EKU `serverAuth`, 1 year; key generated on carlgpu2 by the owner command in §13.B.
- Hub accepts a client only if (a) chain valid, (b) fingerprint is in `node.nodes` with `status='active'` (registered by the owner in the Cockpit after out-of-band fingerprint comparison), (c) not revoked. The agent validates the chain **and** pins the hub's leaf certificate by SHA-256 of its DER encoding (`hub_tls_pins` in the signed policy, §5.3).
- Cert expiry of both sides is a T0 metric and an escalation at 14 days.
- Offline/hub-unreachable: the agent keeps sampling light T0 into the spool and requests no T1/T2/T3 work; `privd` treats an expired lease as STOP ⇒ fail-closed for anything mutating (T0 stays available).

### 5.3 Revocation and trust-anchor rotation (effective, not cosmetic)
A CA-signed replacement certificate does **not** invalidate a stolen one if agents trust the CA. Revocation therefore works on **three independent levers**, all owner-signed and node-enforced:

1. **Hub leaf pin.** The policy carries `hub_tls_pins: [sha256(DER leaf)]` (current + optionally next). The agent refuses any hub certificate whose digest is not listed, even if CA-valid. Replacing the hub certificate = new policy serial with the new pin and without the old one.
2. **Hub gate keys.** The policy carries `hub_gate_keys: [{id, pub, not_after}]` (SSH Ed25519 public keys, namespace `forge-node-hub`). `privd` accepts jobs and leases signed only by listed keys. Removing a key from the policy cuts off everything a thief could sign, independent of TLS.
3. **Trust-anchor rotation.** For a compromised **CA** key: owner generates a new CA on the Mac, installs a **bundle** (`ca.crt` = old+new) on every node (owner command, §13.F), re-signs node and hub certificates under the new CA, then replaces the bundle with the new CA only. Hub accepts clients only under the new CA after the cut-over (hub-side configuration change).

Delivery of a revocation policy must not depend on the compromised hub: the owner applies it **directly on each node** (`privctl policy-apply` over the owner's existing ssh as `carl`, §13.F), and until then `LOCAL_STOP` closes the gap. Node-side hub deny-listing of a node cert (stolen node key) is a hub operation and takes effect immediately; the node key alone can only talk to the hub.

Public: `allowed_signers` on every node and in the hub | signs policy (`-n forge-node-policy`), releases (`-n forge-node-release`), T3 approvals (`-n forge-node-approval`). Distinct namespaces ⇒ a policy signature can never be replayed as an approval |
| mTLS CA key (EC P-256) | owner, Mac, `openssl` | Mac only (offline) | signs node/hub certs |
| Node keys (EC P-256) | **on each node**, by the owner's command, as `forgenode` | `/etc/forge-node/pki/node.key` 0600 | never leaves the node; only CSR/cert move |
| Hub TLS key | owner, on carlgpu2, `openssl` | `forge-core/secrets/nodehub/hub.key` (0640, hub uid) | server identity; leaf pinned by policy |
| **Hub gate key** (SSH Ed25519, no passphrase, service key) | owner, on carlgpu2, `ssh-keygen` | `forge-core/secrets/nodehub/gate_ed25519` (0400, hub uid) | signs jobs and leases (`-n forge-node-hub`); public part lives in each node's signed policy |
| Planner/MCP tokens | existing forge-mcp mechanism | unchanged | who may call `node_*` |

Moving material: only **public** artifacts travel (CSRs, certs, public keys, `allowed_signers`, signed policies, signed releases) via the owner's existing `scp`/`ssh` as `carl`. Fingerprints are compared out-of-band (read on the Mac, compared on the server). Rotation: node cert every 90 days (owner re-signs a fresh CSR; agent reloads); hub TLS cert yearly (policy update for the pin); CA at 4 years with bundle overlap (§5.3); owner key on suspicion: generate new, then T3 manifest `policy_replace_trust` signed by the **old** key replaces `allowed_signers` (the hub alone cannot rotate the owner key). Loss of the owner key = reinstall of `allowed_signers` at each node by the owner as root — the system fails closed meanwhile (no new policy, no T3).

**Compromise playbook.**
- *Planner / prompt injection:* bounded by policy, windows, rate limits; owner `forge-stop`.
- *Hub compromised (gate key or TLS key stolen):* (1) `forge-stop` and `touch /etc/forge-node/LOCAL_STOP` on every node (stops all jobs regardless of leases); (2) build a clean hub, new TLS key+cert and **new gate key**; (3) owner signs policy serial+1 with the new `hub_tls_pins` and `hub_gate_keys` (old removed); (4) apply directly on each node (§13.F); (5) remove `LOCAL_STOP`. Between (1) and (4) the node rejects the old hub by `LOCAL_STOP`; after (4) by pin and key list.
- *Node agent compromised (uid `forgenode`):* it can reach `priv.sock` but cannot originate jobs (hub signature) or fake leases; it can read T0 output and withhold. `privctl lockdown` stops it; `priv.jsonl` (root-written) shows exactly what ran.
- *Stolen node key:* hub deny-list + new CSR; `LOCAL_STOP` on that node if in doubt.
- *Owner key suspected:* §6 rotation via the old key; if the old key is untrusted, reinstall by hand.

### 7.1 What is signed

### 7.2 Protected set evaluation
Evaluated **before** allowlists, on *resolved* objects (realpath of paths, `FragmentPath` and the full systemd transaction of units (§4.3.1), inspected container/network objects, resolved package sets). A protected hit denies even if an allow rule matches. **`/srv/models` and `/srv/kmu-ai` are protected as whole mounts; there is no forge subtree exception.** Changing the protected set requires a new owner-signed policy with `frozen_ack:true`; the hub has no endpoint that edits policy.

### 7.3 Applying a policy
Hub distributes → agent stages it (unprivileged) → `privd policy.apply` (or, for the owner, `privctl policy-apply` as root) verifies: signature against `/etc/forge-node/allowed_signers`, `node` matches, `serial > installed`, `not_before ≤ now`, schema + the rules above → writes the policy to `/etc/forge-node/policy/` atomically (`rename`), updates `/var/lib/forge-node-priv/serial`, rebuilds the derived `dir-ops` property sets → audit. Any failure leaves the previous policy active. There is no sudoers fragment to render. **Rollback is "sign the old content with serial+1"** (monotonic serial prevents replaying an old, wider policy).
Who signs: always the owner in v1. Delegation of low-risk additions to the Betriebsleiter via a limited signing certificate is deferred (OQ-8).

## 8. Audit log

### 8.1 Three independent records, cross-checked by the hub

1. **Agent log** `audit.jsonl` — the agent's own view (relayed jobs, T0 calls, denials at the agent). Directory `/var/log/forge-node-agent/` is **root-owned** (§8.2); the file is `root:forgenode 0660`, `chattr +a`.
2. **Privileged log** `priv.jsonl` — written **only by `privd`** (op units never write it, §8.2). Directory `/var/log/forge-node-priv/` is root-owned; file `root:forgenode 0640`, `+a`. It is the **authoritative** statement of what ran as root; the agent only reads and ships it.
3. **Hub table** `node.audit(node, source∈{agent,priv,hub}, seq, ts, prev_hash, hash, record jsonb)` — role `forge_nodehub` has INSERT/SELECT only; `UPDATE/DELETE/TRUNCATE` revoked and blocked by trigger; unique `(node, source, seq)`; monthly partitions; retention ≥ 400 days. A verification job recomputes the chains and **cross-checks**: every T1/T2/T3 job in `node.jobs` must have matching `priv` intent+result (or a recovery record, §8.4) with the same `job_id`/`attempt`, and every `priv` record must map to a job or an owner-signed T3. Mismatch ⇒ node **quarantine** (lease `quarantine:true`) + `node_alert`.

Record fields: `fmt` (format version), `ts` (UTC + Berlin offset), `node`, `seq`, `type` (`intent|result|denial|t0|chain_link|recovery|tail_repair|lease|policy|release_switch`), `job_id`, `attempt`, `fence`, `requester`, `tier`, `op`, params (redacted), `policy_serial+sha256`, `decision` + `reason_code`, `dry_run`, `plan_hash`, start/end, exit, stdout/stderr sha256 + redacted excerpt ≤ 4 KiB, pre/post state digests, lease `seq` seen, cert fingerprint, agent/release version, `prev_hash`, `hash`.

### 8.2 One serialized writer per log; root-controlled paths

**No agent-owned directory anywhere in the privileged path.** (The first revision made `/var/log/forge-node` agent-owned and used shared locks; a compromised agent could then replace directory entries or lock files during rotation, and two writers could allocate the same `seq`/predecessor hash.) The layout (rev 6: one directory per generation, forced by the kernel facts in §8.3):

| Path | Owner / mode | Who writes | Notes |
|---|---|---|---|
| `/var/log/forge-node-priv/` (dir) | `root:forgenode 0750` | root only | agent can traverse/read, not create, rename, link or unlink |
| `…/priv.<n>/` (generation dir, `n` = 6 digits) | `root:forgenode 0750` (**0700 while it is being built**) | root only | reachable by the agent only once its file carries `+a` |
| `…/priv.<n>/priv.<n>.jsonl` | `root:forgenode 0640`; **live: `+a`; sealed: `+a +i`** | `privd` only | active file named by `CURRENT` |
| `…/CURRENT` | `root:forgenode 0644` | `privd` (atomic `rename` inside the root-owned dir) | `{"dir","file","fmt","gen"}` canonical JSON |
| `/var/lib/forge-node-priv/locks/priv.log.lock` | `root 0600` in a root-only dir | `privd` | the only lock for `priv.jsonl` |
| `/var/log/forge-node-agent/` (dir) | `root:root 0755` | root only | agent has no write permission on the directory |
| `…/audit.<n>/audit.<n>.jsonl` | `root:forgenode 0660`, live `+a`, sealed `+a +i` | the agent process (O_APPEND) | active file named by `CURRENT` |
| `…/audit.lock` | `root:forgenode 0660` (created by root in the root-owned dir) | agent (flock) and root | the agent can open and lock it but cannot replace, unlink or rename it |
| `/var/lib/forge-node/` | `forgenode` | agent | spool, staging, `audit-acks.json` only; **never consumed by `privd` by path** |

Rules:
- **Single serialized writer.** Each log has exactly one writer *process* (`privd` for `priv`, the agent for `audit`); inside it a single mutex owns the sequence. In addition every append takes `flock(LOCK_EX)` on the log's lock file **around the whole critical section**: re-read `CURRENT`, re-validate the cached head `(inode, size)` against the file (mismatch ⇒ re-scan the tail), allocate `seq` and `prev_hash`, one `write()` on the `O_APPEND` descriptor, `fsync`, update the head cache, unlock. A second writer instance (restart overlap, root's recovery appending a `recovery` record, a hostile second process of the same uid for the agent log) therefore cannot allocate the same `seq`. The head is found by **following the chain forward** — from the start of the file (its first record must be the `chain_link` at offset 0) or from the writer's cached head: a record continues the chain only if its `seq` is the previous `seq + 1` **and** its `prev_hash` is the previous record's hash. Anything else — junk, a torn write, a self-consistent record a hostile writer appended with an invented *or rewound* `seq`/`prev_hash` — is damage and can neither become nor move the head (a rewound forgery used to fork the agent log). The cache is only a starting point and ends exactly where the writer's own `O_APPEND` write ended (`lseek`), so bytes another writer appended between our write and our next look are read, never swallowed. Damage has no size limit; it is streamed (hashed in 1 MiB chunks), never held in memory or capped — a cap would let one hostile process of the agent uid make the log un-rotatable.
- **Op units never write `priv.jsonl`.** An op reports to `privd` only through its per-attempt `status.json`; `privd` appends the audit lines (intent before the unit starts, result after).
- `privd` and `privctl` **never take agent-supplied paths**: the agent sends policy blobs and requests as bytes over the socket. For root CLI calls (`privctl policy-apply /tmp/…`) both files are opened with `O_NOFOLLOW|O_NONBLOCK`, must be regular files, are read fully into memory, and signature, schema and installation all operate on **those bytes**.
- Every path walk in the privileged code uses a `dirfd` opened `O_DIRECTORY|O_NOFOLLOW` and descriptor-relative opens with `O_NOFOLLOW`, then `fstat` (type, owner `root`, `nlink == 1`, exact mode). The directory chain from the log directory up to `/` must be root-owned and not group/other-writable (`audit.log.trusted_chain`).
- **Durable intent before action:** for any mutating op `privd` appends the `intent` record and fsyncs it *and* records `started` in the ledger *before* the worker unit starts (pipeline steps 6 and 17). If the intent cannot be written, the op is refused (`DENY_AUDIT_DOWN`, retryable). Once an intent exists, every exit writes a `result` record that closes it; a denial before any intent is a `denial` record (the hub's cross-check accepts `denial` or `result` for denied jobs). Denial records are rate-limited (60/min, the rest summarised) so garbage requests cannot become an audit flood.

### 8.3 Rotation without a vulnerable window (gate D protocol, rev 6)

**Kernel facts the protocol rests on** (observed on a real ext4 by `audit/fsproof.py`, which `privctl audit-init` and `doctor` re-run on the log filesystem; the tests assert them): (1) on an append-only inode (`+a`) `open()` for writing without `O_APPEND`, `chmod`, `chown`, `truncate`, `rename`, `unlink` and `link` fail with `EPERM`; (2) **permissions and `+a` are checked at `open()`: a descriptor opened for writing *before* `+a` was set can still overwrite in place afterwards** — so a log file must never be reachable by a writer before `+a` is set; (3) **`+i` (immutable) refuses every write through *any* descriptor, however old, with or without `O_APPEND`** (`EPERM`), is added to an inode that already has `+a` (so the file is never writable without a flag), needs no `chmod`/`chown`, and `fsync`/reads keep working. Setting either flag needs `CAP_LINUX_IMMUTABLE`; `privd`'s unit has exactly `CAP_LINUX_IMMUTABLE CAP_CHOWN`.

**Seal = `+a +i`.** Revision 3's `fchmod 0440` is superseded (the kernel refuses it, and mode bits cannot stop a writer that already holds a descriptor). **Rotation** (root, holding the log's exclusive lock throughout; no rename of any log file — only the small `CURRENT` pointer is replaced):
  1. re-read `CURRENT` and the live file's tail (not the cache); a damaged tail gets its `tail_repair` record **before** the file becomes immutable;
  2. **seal** the old file: add `+i` — from here nobody can change it, however many descriptors exist (the cooperative writers are blocked on the lock anyway; a hostile holder gets `EPERM`);
  3. read the sealed file's final tail and its sha256/size (definitive now; bytes a hostile holder slipped in before the seal are accounted for in the next file's `chain_link`: `prev_damaged_bytes`/`prev_damaged_sha256`);
  4. create `<prefix>.<n+1>/` (`0700`), create the file inside it (`O_CREAT|O_EXCL|O_NOFOLLOW`, mode and group by `fchmod`/`fchown` on the **still unflagged** new inode), write its first record `chain_link {gen, prev_file, prev_seq, prev_file_sha256, prev_file_bytes, prev_damaged_*}` continuing seq and hash, `fsync` file and directory;
  5. set `+a` on the new file, **then** make its directory reachable (`fchmod` `0750`/`0755`), `fsync`;
  6. atomically replace `CURRENT` (temp file in the same root-owned directory, `rename`), `fsync` the directory.
  There is never a moment in which an existing log file can be written without a flag, and none in which another uid can open a log file that is not yet `+a` (it sits in a `0700` directory). The agent never has write permission on a directory in this path, so directory-entry replacement by the agent fails with `EACCES/EPERM`. Appenders re-read `CURRENT` after taking the lock; a sealed or flagless live file is `AuditDown` for them (fail closed) until root recovers.
- **Crash at any system call** (tests: SIGKILL before and after each of the 25 mutating calls of a rotation, and again inside the recovery of each state) — `recover()` is idempotent, runs at `privd` start and on every heal, and rolls forward from the self-describing state: *`CURRENT`→n live, nothing newer* ⇒ nothing (a stale `CURRENT.tmp` is removed); *n sealed, no n+1* ⇒ resume at step 3; *n sealed, n+1 incomplete* (unreachable, unflagged — the only way back is removing it) ⇒ remove and resume at step 4; *n sealed, n+1 complete* ⇒ finish steps 5/6. A missing `+a` on the active file is set. Anything else — a gap, a live file with a successor, `CURRENT` missing while files exist, a successor whose `chain_link` does not match the sealed predecessor, `CURRENT` naming a file without a `chain_link` — is `AuditCorrupt`: quarantine, owner decision. A `recovery` record `{actions}` is appended whenever anything was done.
- **Purge** of sealed generations (≥ 90 days by their last record **and** hub-acknowledged up to their last `seq`, oldest first, never the active file or its direct predecessor): `privd` opens the directory by `dirfd`, checks the entry (regular, `root`, `nlink==1`, sealed flags), **hides the generation directory (`fchmod 0700`) before any flag is cleared**, clears `+a +i` through the opened descriptor immediately before `unlinkat`, then `rmdir`. A crash anywhere in this sequence is finished by `recover()`: an empty generation directory is removed; a file whose flags were cleared is re-sealed and its directory made reachable again (nobody can have opened the flagless file: the directory was hidden); a hidden directory that still holds a sealed file is made reachable again. The acknowledged value comes from the hub (`privctl audit-purge --acked-priv N --acked-agent M`; an older value only errs on the safe side — acks are monotonic); a value beyond the log's own head is refused (a typo must not purge files the hub never acknowledged). It refuses unacknowledged files.
- **`audit-init` is crash-safe like rotation:** generation 1 is built unreachable (`0700`) and flagged before it becomes reachable, `CURRENT` is written last; a re-run after a crash finishes or rebuilds an unreachable/unused generation 1 (it never adopts a log that has been written to: `CURRENT` missing next to a used generation is `AuditCorrupt`).
- **Damage at the seal:** bytes a hostile writer appends after the final tail repair and before the seal are described by the next file's `chain_link` (`prev_damaged_bytes`/`prev_damaged_sha256`), however large; the reader skips an unterminated fragment at the end of a sealed generation (a generation that has a successor is final) instead of waiting for it.
- **`doctor` / `selfcheck audit` never repair:** besides the filesystem proof (canary in a root-only scratch directory next to each log; stale canaries of a killed proof are swept) it opens each live log with `peek()` — CURRENT, owner/mode, the append-only flag — which, unlike `head()`/`append()` on the root side, runs no recovery. The proof also covers the live-file escape routes (`fallocate` punch/zero/collapse/insert, `RWF_NOAPPEND`, clearing `O_APPEND` then overwriting) and treats what a descriptor opened *before* `+a` may do as informational — the protocol does not depend on it.
- **Rotation triggers:** size (`max_file_bytes`, 64 MiB) or age (24 h, only if the file holds more than its `chain_link`); `forge-node-audit-rotate.timer` runs `privctl audit-rotate due` hourly.

### 8.4 Failure and recovery
- **Missing result record** (crash between effect and result): at `privd` start (and on `reconcile`), every ledger row in `started`/`effect_done` is handled by the **worker-aware reconciliation of §9.4** (never by a bare probe); `privd` then **appends** a `recovery` record (`reconciled_applied | aborted_safe | indeterminate`) referencing the intent. Nothing is rewritten. The hub treats an `intent` without `result`/`recovery` older than 10 minutes as an open anomaly.
- **Torn tail** (partial last line after power loss): readers validate the last line; a damaged tail of any size is left in place (`+a` forbids truncation) and a `tail_repair` record `{bytes, inserted_newline, sha256}` of exactly the bytes observed is appended (bytes slipped in after the observation are `foreign`: tolerated and counted in the agent log, a verification problem in the priv log); the chain continues from the last valid hash.
- **Gaps:** a `seq` gap or hash break detected by the hub ⇒ quarantine + alert; the node's local files are evidence.
- **Shipping (N3):** the agent reads both logs through the generation directories (read permission only) and posts chain-continuing records in batches of ≤ 200 to `POST /v1/audit`; the highest acknowledged seq per log is kept in `/var/lib/forge-node/audit-acks.json`; junk, torn tails and unlinked forgeries are never shipped; the poll heartbeat carries both heads.
- **Hub unreachable:** audit records stay on the node (not dropped). The 50 MiB ring applies only to the **T0 spool**. If unacknowledged audit exceeds 500 MiB the node refuses mutating ops (`DENY_AUDIT_DOWN`).
- **Fail-closed:** if the agent cannot append locally, non-T0 relays stop; if `priv.jsonl` cannot be appended, `privd` refuses to act. Redaction happens before write and again at the hub; raw output is never stored.

## 9. Safety controls

### 9.1 Kill switch (control/STOP)
- **Global:** the hub reads `/srv/forge/post/control/STOP` (same bind-mounted control **directory** as forge-mcp; file exists ⇒ active; `touch` activates; `rm` releases; unreadable ⇒ active). Before a job is signed the hub takes the existing **`.dispatch.lock`** (flock) from the last STOP check until the job row is committed `issued`, so a Stop either precedes the check (job refused) or follows the committed job. Every lease carries the current `stop` flag.
- **Node reaction is enforced by `privd`, not by the agent:** with `stop=true`, an expired lease, a non-monotonic `seq`, `LOCAL_STOP`, or `quarantine`, `privd` denies all T1/T2/T3 work (`DENY_STOP`, `DENY_STALE_LEASE`, `DENY_LOCAL_STOP`, `DENY_QUARANTINE`) even when called directly on the socket. In-flight ops finish their current atomic step and do not start the next (`abort_on_stop` per op). **T0 continues** (rate-limited).
- **Per project:** `stopped_projects[]` in the lease; jobs carry `project`.
- **Local:** `touch /etc/forge-node/LOCAL_STOP` (owner, on the server) blocks T1/T2/T3 regardless of the hub; `privctl lockdown` additionally stops the agent and disables `privd.socket` (§13.E).
- **Staleness:** lease `valid_until` ≤ 60 s; no fresh lease ⇒ STOP assumed. Reboot clears `/run/forge-node/lease` ⇒ fail-closed until a new lease.
- **Who can release:** only the owner/Cockpit/`forge-release`; a node cannot touch `control/` (no mount, no endpoint). Nodes can only set their own **quarantine**; global STOP is not automated from node signals (a compromised node must not be able to DoS the fabric) (M-92).

### 9.2 Rate limits (authoritative in `privd`, mirrored at the hub)
Token buckets per op from policy, e.g.: T1 mutating ≤ 6/min, ≤ 60/h per node; `unit.restart` of the same unit ≤ 2 per 10 min and ≤ 6/day; `container.stop` ≤ 5/h/node; `vm.destroy` ≤ 1/h; `docker.prune_apply` ≤ 1/week; deletions ≤ 5 GiB/day/node; **one mutating op per node at a time** and one per `effect_key`; T0 heavy ≤ 1/10 min, light ≤ 2/min. Bucket state lives in the root-protected ledger DB (rate events table) — an agent restart or a direct socket call cannot reset it. Per-identity quotas at the hub.
**Circuit breaker:** 3 consecutive `FAIL_*` of an op ⇒ `privd` flips the op to `dry_run_only` (ledger table `circuits`) and the hub raises a `node_alert`; re-enable only by Betriebsleiter acknowledgement, never by the failing caller.

### 9.3 Dry-run and plans
Every mutating op implements `dry_run` through the single effect path inside its op unit (no second code path). Dry-run returns `{plan, plan_hash, expires 30 min}` and `privd` **stores the plan** (root state); apply must present the hash and `privd` recomputes the plan — mismatch ⇒ `DENY_STALE_PLAN`. Ops start `mode: dry_run_only`; promotion to `enforce` is a policy change signed by the owner. `global_mode: observe` forces dry-run for everything (`privd` applies this at step 8, so a direct socket call cannot escape it).

### 9.4 Durable execution ledger — exactly-once effects, worker-aware reconciliation

**Problem.** "Hub returns the existing result for a repeated `job_id`" only covers completed results. If an effect succeeds and the result is lost, a retry would run it again. Round 1 added a ledger with probes; the verification showed the remaining hole: op workers are **transient systemd units that outlive `privd`**. A bare probe that sees the *unchanged pre-state* of a worker that is still running (or has not yet reached its effect) would conclude "not applied", permit a new attempt, and both workers would then produce the effect. Also, effects delegated to other daemons (a queued systemd job, a Docker API call) continue after the worker's process is gone.

**Contract.** The authoritative ledger is `ledger.sqlite` in `/var/lib/forge-node-priv` (stdlib `sqlite3`, WAL, `synchronous=FULL`, `root` 0600). Tables: `exec(job_id PK, attempt, op, effect_key, params_sha256, state, fence, worker_unit, worker_invocation_id, worker_started_at, worker_dir, plan_hash, pre_digest, post_digest, result_json, claimed_at, updated_at, delivery_seq)`, `rate_events`, `circuits`, `plans`, `t3_nonces`, `target_locks(effect_key PK, job_id, reason)`.

States: `received → started → effect_done → committed` (terminal), plus `reconciling`, `denied_retryable`, `denied` (terminal), `failed` (terminal, effect known not applied or rolled back), `aborted_safe` (worker confirmed dead **and** probe says not applied; retryable with `attempt+1`), `indeterminate` (blocks the target).

**Worker identity and fencing (persisted before the worker starts).**
- The worker is started as a transient unit with the deterministic name `forge-node-op-<job_id>-<attempt>.service`, **without `--collect`**, so its state stays queryable after exit. In the same ledger transaction that records `started`, `privd` stores `worker_unit`, `worker_dir` (`/var/lib/forge-node-priv/work/<job_id>-<attempt>/`, root-only) and the current `fence` (a per-row integer). After `systemd-run` returns, `worker_invocation_id` (`InvocationID`) and `worker_started_at` are stored. The worker writes its outcome atomically to `worker_dir/status.json` (`write temp`, `fsync`, `rename`) as its last act and never anywhere else.
- **Effect lock.** Immediately before the effect step the worker takes `flock(LOCK_EX)` on `/var/lib/forge-node-priv/locks/fx-<effect_key_hash>.lock` (root-only directory) and, **while holding it**, re-reads its ledger row (read-only open): the effect proceeds only if `state ∈ {started}` and `fence` equals the fence it was started with. It holds the lock until the effect step ends. The lock lives in the worker's process, so it survives `privd` dying.
- **Reconcile bumps the fence first.** Reconciliation (below) increments `fence` and sets `reconciling` in one transaction **before** it looks at the world. A surviving worker that reaches its fence check later sees the mismatch and exits without performing the effect (`FAIL_FENCED`, recorded in `status.json`).

**Active vs interrupted execution.** `privd` asks systemd about the persisted unit (`ActiveState`, `SubState`, `InvocationID`, `Result`, `ControlGroup`):
- `activating|active|deactivating` with the **same** `InvocationID` ⇒ **active execution**. No reconciliation, no probe, no new attempt: the row stays `started`; duplicate deliveries get `in_progress`; `privd` (re)attaches by polling the unit until it ends or the op's `timeout_s` elapses.
- Unit gone/`inactive`/`failed` and `status.json` present and complete ⇒ **finished**: `privd` reads it and commits (`effect_done` → `committed`/`failed`).
- Unit gone/`inactive`/`failed` and `status.json` missing or incomplete, or timeout reached ⇒ **interrupted** ⇒ reconciliation.

**Reconciliation procedure (the only way a row leaves `started/effect_done` without a result).**
1. Take the per-job reconcile lock (`flock` on `/var/lib/forge-node-priv/locks/job-<job_id>.lock` **and** `BEGIN IMMEDIATE`), so duplicate delivery, `reconcile` requests, startup recovery and retry claims are **serialized**; a concurrent caller gets `in_progress`.
2. Bump `fence`, set `reconciling` (commit).
3. **Establish that the worker is dead:** if the unit is still active, `systemctl stop` it (the unit has `KillMode=control-group`, `SendSIGKILL=yes`, `TimeoutStopSec=30`) and wait until `ActiveState` is `inactive|failed` **and** the unit's cgroup is empty. If the unit cannot be confirmed dead ⇒ state `indeterminate` (never `aborted_safe`).
4. Take the effect lock `fx-…` (now free; if it is somehow still held by a process outside the cgroup ⇒ `indeterminate`).
5. **Settle delegated effects** (op-declared, bounded): `unit.*` waits until the target unit has no pending job (`systemctl show -p Job`, `list-jobs`); Docker ops wait until no container of the target is in a transitional state (`restarting|removing|created` without start) ; compose waits for the project's container set to be stable twice in a row; `dir.*` has no delegate. Settling that does not converge ⇒ `indeterminate`.
6. Run the op's **probe** and classify (table below). Verdicts: `applied` ⇒ `committed` (reconciled), `not_applied` (state digest equals `pre_digest`) ⇒ `aborted_safe`, `partial|unknown` ⇒ `indeterminate`. Append the `recovery` audit record.
7. Release locks. **A new attempt may start only from `aborted_safe`, only through the same serialized claim path, with `attempt+1` and the already bumped `fence`.**

**Startup recovery.** At `privd` start it enumerates `forge-node-op-*.service` units from systemd **and** the open ledger rows, matches them by name and `InvocationID`, re-attaches to the active ones (does not touch them), and applies the interrupted-path to the rest. A unit with no ledger row is stopped and raises a `node_alert`; a ledger row whose unit is missing is "interrupted". No row is ever treated as "not applied" merely because `privd` itself restarted.

**Idempotency classes and probes (declared per op in the op table):**

| Class | Meaning | Examples | After confirmed-dead worker |
|---|---|---|---|
| `natural` | repeating is harmless | `container.start|stop`, `dir.ensure`, `image.pin`, `file.put` (same hash), `volume.grow` to the same size, `policy.apply` (same serial) | probe or simply re-run |
| `probe` | effect observable via state | `unit.restart` (new `InvocationID`/`ActiveEnterTimestamp` after `claimed_at`), `container.restart|recreate` (`StartedAt`/container id after claim, config hash equals plan), `stack.up` (services match rendered-model hash), `dir.trash` (source absent ∧ trash manifest present), `volume.create` (image + mount registry entry match), `scene.switch` (scene marker + VRAM proof), T3 manifests (per-kind probes) | `applied` ⇒ `committed`; `not_applied` ⇒ `aborted_safe`; `partial`/`unknown` ⇒ `indeterminate` |
| `resume_same_plan` | item-wise idempotent plan | `docker.prune_apply`, `dir.purge_trash` | re-run only the **same stored plan** (removing an absent item is a no-op); never a recomputed plan |
| `opaque` | effects unknown | opaque T3 | crash ⇒ always `indeterminate`; never retried automatically |

**`indeterminate` handling.** The `effect_key` gets a `target_locks` row: every further op on that target is denied (`DENY_TARGET_LOCKED`) until it is resolved by (a) a repeated reconciliation that now gives a verdict (N3: an `indeterminate` row is reconciled again by the next `reconcile` request, at most once per 5 minutes because every look appends a `recovery` record; a verdict releases the target), (b) the Betriebsleiter's `ledger.resolve` (T2-class, read-only inspection attached), or (c) an owner T3. The hub raises a `node_alert` (inbox) with the probe evidence and the worker's final `status.json`.

**Hub/agent side.** The hub's `node.jobs` mirrors the states, including `in_progress`. The hub **never** creates a new `job_id` for the same graph effect while the node reports a non-terminal state; re-delivery uses the **same `job_id`** with `delivery_seq+1` (fresh `issued_at/expires_at`). `open_jobs` in each poll lets the hub spot "claimed but no result" and ask `reconcile[]`; the node answers from the ledger (and, if the row is interrupted, runs the serialized reconciliation) — never from agent memory. Terminal rows are kept ≥ 90 days; a job with expired `expires_at` is rejected regardless, so replays of old deliveries are impossible.

**Graph mapping.** `job_id = uuid5(graph thread, node, attempt-key)` (F5C2 §3.6 effect keys), so graph at-least-once execution maps to node exactly-once execution.

### 9.5 Windows
Berlin local time via `zoneinfo` (not fixed offsets; DST ended 2026-10-25). **Mutating ops (T1/T2/T3) are denied 02:00–05:45 daily and Sundays before 06:00** (KMU backup window; BETRIEBSHANDBUCH "Sperrzeiten", ADR §9). Heavy T0 follows the same blackout; light T0 does not. **ADR-027:** the owner opened 03:00–03:45 for *training GPU load* (no checkpoint writes) — that is F5q workload on the GPU, not a node operation; the node blackout is unchanged, and the node's light T0 sampling does not interfere. No change while a pipeline job runs (checked per op via unit/queue state where known). There is no apt window (§4.3).

## 10. Protecting KMU frozen areas and Live-Trading (carlgpu4)

Defense in depth — each layer independent:

1. **Not installed.** carlgpu4 and carlgpu1 get the **`t0` artifact** (a separate signed tarball): agent, `privd`, `privctl`, and an op table containing only read-only probes, `policy.apply`, `audit.rotate`, `lockdown`. The mutating op scripts (T1/T2/T3 execution) are **not in the tree**, `t3.opaque_enabled` is rejected by the policy schema for this profile, no docker group membership, `tiers_enabled:[0]` in the signed policy. Nothing to "misconfigure into" T2. There is no sudo anywhere (§4.4), so g4's Ubuntu 26.04 sudo-rs question is moot.
2. **Deny by default.** No op takes a free-form path, unit, container, image, command or port; each target must match an allowlist entry. There is no "exec", no "shell", no generic `systemctl`.
3. **Protected set first** (§7.2): `/opt/kmu-ai/**`, `/srv/kmu-ai/**`, **`/srv/models/**` as a whole mount (no forge subtree, OQ-1)**, `/srv/tradebot/**`, `kmu-*`, `tradebot-*`, `secmpro*`, `nexus*`, `ollama`, DBs, nginx, NFS, sshd, docker/containerd, networks `tb-gate0`/`tb-int0` and `172.31.250–252.0/24`, Docker daemon config, users `carl|kmuai|tbpost`, secrets directories. Evaluated on resolved objects (realpath, `FragmentPath` + the full systemd transaction, container inspect, resolved package sets), so a symlink, bind mount or rename cannot dodge a name match; each forge root's backing image must lie on the root filesystem and its mounted volume's device must differ from every protected mount's device.
4. **Frozen = metadata only for T0.** For protected paths T0 may report `stat`, `df`, git rev + tracked-dirty count (no index writes), unit state, and — for the Revision's model inventory (`inv.models`) — directory names (depth ≤ 2), sizes and mtimes of `/srv/models` read with `ionice -c3` outside the window. Never file contents, never exec inside, never `docker exec/cp`. Container `Env`/`Cmd` are never collected.
5. **No GPU actions on g1/g3/g4** by T1/T2 (VRAM budgets 0 there). GPU allocation on g2 only within `vram_budget_mib`. F9-S4's precondition "Live-Trading needs no GPU" becomes a pure T0 evidence item.
6. **Owner-only, double-keyed.** Any T3 whose resolution (§4.6) yields a protected hit needs `frozen_ack:true` inside the owner-signed blob; opaque commands always need `opaque_ack` **and** `frozen_ack` and do not exist on the `t0` profile. The hub/Betriebsleiter can *prepare* the command but cannot satisfy it (ADR-024 "Owner-Vorbehalte": Live-Trading, Geld, Secrets, Konten, root).
7. **No daemon-wide side effects.** The node never restarts `docker`/`containerd`, never edits `daemon.json`, never touches `iptables` outside the owner-run `forge-docker-user.sh` (T3 `firewall_apply`), never changes sshd or sudoers. Package updates are **not performed** (§4.3); `unattended-upgrades` stays the host's own mechanism.
8. **Footprint guard on g4.** Agent ≤ 96 MiB RSS and 15 % CPU of one core at `Nice=19`; install only after `free -m` shows headroom (swap is nearly full) — otherwise the owner defers g4 (OQ-3: last, read-only).
9. **Alarms instead of actions:** anomalies on protected hosts (new listener, failed unit, backup age, swap, cert expiry, dirty/rev change on `/opt/kmu-ai`, `unattended-upgrades` drift or failure) produce T0 findings and inbox alerts, never repair actions.

## 12. Threat model (condensed)

| Threat | Mitigation | Residual |
|---|---|---|
| Prompt injection via log/inventory text makes a planner ask for harm | outputs are data in an `untrusted` envelope, charset-filtered; closed op table, no free-form execution; policy + protected set + windows + rate limits | planner can request *allowed* ops repeatedly → rate limits/circuit |
| Planner asks to stop a critical service (postgres, edge) | `forge.critical`, enumerated units only, full-transaction check incl. `Conflicts=`, `requires: owner_signature` | owner approval needed |
| Agent (uid `forgenode`) compromised, calls `privd` directly | `privd` re-runs the full pipeline from root state; jobs/leases are hub-signed, so the agent cannot originate work or fake "not stopped"; rate/circuit/ledger are root-held | agent can withhold (fail-closed) and read T0 data |
| Hub compromised / gate key or TLS key stolen | node-local signed policy, windows, rate limits, `privd`-held ledger, `requires: owner_signature` on high-impact ops; **revocation by policy** (leaf pin + gate-key list, applied directly by the owner, §5.3) with `LOCAL_STOP` as immediate stop | on **g2** the executor `forge` (docker group = root-equivalent, ADR-008) can read hub material and bypass the *hub*; tiers there bound the API path, not that account (OQ-10: remove `docker` from `forge` later) |
| Direct-sudo / argument-injection bypass | there is **no sudoers entry** for `forgenode`; one socket, one `gate()` for every op; static test over the op table | `privd`/op-script bugs → tests §16, cross-model review (G6) |
| Docker-compose as root escalation | resolved-model lint, key allowlist, no `docker` group for the agent, rendered file applied, no named volumes | lint completeness → named tests |
| Opaque T3 hides protected effects | disabled by default, absent on `t0` profile, requires `opaque_ack` + `frozen_ack`, empty env, timeout, single-use nonce; manifests preferred and resolved independently | an owner who signs an opaque blob accepts the risk |
| Interrupted effect repeated (double restart/prune) | durable ledger, atomic claim, probes, reconciliation before retry, `indeterminate` locks the target | probes can say `unknown` ⇒ human decision |
| Symlink/TOCTOU in dir ops | `O_NOFOLLOW` walk, `st_dev` check against root and protected devices, act on IDs | kernel races mitigated by dir fds |
| Policy rollback / downgrade | monotonic serial in root-only store; schema rules | owner key loss fails closed |
| Audit tampering / loss | `+a`, chain, root-written priv log, hub INSERT-only, cross-check, rotation chain links, recovery records | root on the node can destroy local logs; hub copy survives |
| Clock manipulation | lease `issued_at` skew ≤ 60 s; NTP metric | |
| Cert theft | 90-day certs, fingerprint registry, deny-list, hub leaf pin | |
| Running workload exhausts the system disk | fully allocated per-node and per-workload loop-ext4 volumes (kernel `ENOSPC`), `read_only` rootfs, sized tmpfs, Docker log rotation, anonymous-volume rule; workload-start ops disabled until these exist (§4.2.1) | OS/Postgres/backups on `/` are not affected by workloads; the reserved image space is lost to other uses |
| Node causes load on g4 | cgroup limits, last rollout, T0 only | swap-bound host: owner may defer |
| Start of an allowed unit stops a protected one (`Conflicts=`) or pulls one in (`Requires=`/`Wants=`) | full transaction resolver, fail-closed on incomplete resolution, `closure_sha256` pinned, protected-state snapshot compared after the op (§4.3.1) | new graph edges after signing ⇒ `DENY_CLOSURE_CHANGED` until re-signed |
| `privd` dies while a worker is alive; retry doubles the effect | persisted worker identity, fence + effect lock, kill-and-confirm-dead + settle before probing, serialized reconcile/retry (§9.4) | unconfirmable death ⇒ `indeterminate` (human) |
| Agent tampers with log directories, locks or rotation | root-owned directories and lock files, one serialized writer, no live-file `-a` window, `dirfd`/`O_NOFOLLOW` (§8.2–8.3) | agent can write lines into its *own* log (hub cross-check vs priv log) |
| Unattended upgrades touch docker/nvidia | forge-node does not change that mechanism; reports drift/failures (OQ-12 decided) | host policy, outside forge-node |

### 13.E Rollback and uninstall

**Levels (each independent, each reversible):**
1. **Pause everywhere:** `/srv/forge/work/forge-ops/bin/forge-stop "forge-node pause"` (release: `forge-release`). T0 still works.
2. **Pause one node:** `sudo touch /etc/forge-node/LOCAL_STOP` (resume: `sudo rm`). Enforced by `privd` itself.
3. **Lockdown one node (no T1/T2/T3 at all):** `sudo /opt/forge-node/current/bin/privctl lockdown` — creates `LOCAL_STOP`, stops the agent, disables `forge-node-privd.socket`. Manual equivalent if the tool is unavailable: `sudo touch /etc/forge-node/LOCAL_STOP && sudo systemctl disable --now forge-node-agent.service forge-node-privd.socket forge-node-privd.service`. There is no sudoers fragment to remove.
4. **Revoke:** Cockpit /nodes → Revoke (hub deny-list); hub or key compromise: §5.3 and §13.F.
5. **Release rollback / upgrade (version-consistent).** *Everything version-bound lives inside one release directory* `/opt/forge-node/releases/<ver>/` — agent zipapp, `privd`, op table, op scripts, `privctl`, systemd unit files, policy schema. Nothing version-bound is copied elsewhere (the one deliberate exception is the release switcher, below): units are installed with `systemctl link` pointing into `/opt/forge-node/current/…`, and `current` is a symlink. One switch therefore moves **agent, helpers, units and op table together**:
```bash
OLDVER=0.1.0                                                   # the version to go back to (see 'status')
sudo /usr/local/sbin/forge-node-release status                 # current, previous, state schema versions
sudo /usr/local/sbin/forge-node-release check  "$OLDVER"       # dry-run: signature of the old release manifest, profile match, state-schema window, policy schema supported
sudo /usr/local/sbin/forge-node-release switch "$OLDVER"       # quiesce (stop agent, drain privd: refuses while an op is 'started'), repoint 'current', daemon-reload, start, run doctor
```
`switch` refuses when (a) the target's signed manifest does not verify (the release directory and its ancestors, `allowed_signers`, `RELEASE.json` and its signature must be root-owned and not writable by others; a missing profile file, an unreadable installed policy or an unreadable ledger table refuse too — a guard whose input is missing does not pass), (b) a ledger row is non-terminal — read after **everything** that can create one (agent, privd socket and service, the rotation timer) has been stopped, (c) the **state schema** is outside the target's supported window, (d) `/etc/forge-node/node.env` has no usable `FORGE_NODE_NODE_ID`. After the first change the switch is transactional: ANY failure (a unit that does not start, doctor) takes the previous release back (verified again); if the way back fails too, everything is stopped (a quiet node) and the exit status is 3 (1 = restored, 0 = switched). `doctor --after-switch` runs as `forgenode` with the `FORGE_NODE_*` environment of `node.env`; there the environmental checks (clock, identity, hub) only warn — a hub outage is not a reason to roll a release back — while everything a release can break still fails. **State compatibility rule:** `ledger.sqlite` carries `PRAGMA user_version`; each release declares the `state_min..state_max` it can run on. Schema changes are **expand-only** in the release that introduces them (new columns/tables with defaults, ignored by older releases); contracting changes ship two releases later, after the older one is no longer a rollback target. The audit/priv record `fmt` version and the policy `schema` follow the same rule. A rollback never edits, truncates or replaces the ledger, the logs or the policy; the audit chain simply gets a `release_switch` record. Upgrade = unpack the new release next to the old one, `check`, `switch`, observe, keep the old directory until the next release is stable.

**The switcher is the one component installed outside the release tree** (`/usr/local/sbin/forge-node-release`), because it must be able to switch *any* release including a rollback to one older than itself. Its **compatibility contract**: it is minimal (shell/stdlib, a few hundred lines, no dependency on release internals); it reads only each release's `RELEASE.json` (`release`, `profile`, `switcher_api`, `state_min`, `state_max`, `policy_schema`, unit list, signed manifest) and drives units via `systemctl link`; `switcher_api` is an integer and the switcher supports its own value and all lower ones. A release that needs a newer `switcher_api` makes `check` refuse with the instruction to run `sudo forge-node-release self-update <ver>` (verifies the release's signed copy of the switcher against `allowed_signers`, installs it atomically, keeps the previous one as `forge-node-release.prev`). A normal release never requires a switcher change; rollback of the switcher itself = `mv forge-node-release.prev forge-node-release`.
6. **Uninstall a node completely:**
```bash
sudo /opt/forge-node/current/bin/privctl lockdown
sudo systemctl disable --now forge-node-audit-rotate.timer forge-node-agent.service forge-node-privd.socket forge-node-privd.service
for u in $(systemctl list-unit-files --no-legend 'forge-node-*' | awk '{print $1}'); do sudo systemctl disable "$u" 2>/dev/null; done
sudo systemctl daemon-reload
sudo chattr -a /var/log/forge-node-priv/*.jsonl /var/log/forge-node-agent/*.jsonl
sudo tar -czf /root/forge-node-audit-$(hostname)-$(date +%Y%m%d).tgz -C /var/log forge-node-priv forge-node-agent          # keep the evidence
sudo rm -f /usr/local/sbin/forge-node-release
FORGE_ROOT=/srv/forge/node                                             # g3: /var/lib/forge-node/data; g1/g4: skip the next two lines
sudo systemctl disable --now "$(systemd-escape -p --suffix=mount "$FORGE_ROOT")"   # only after all forge stacks are down; the volume image is KEPT
ls -l /var/lib/forge-node-img/                                         # delete the image deliberately (and the mount unit) only when the data is not needed
sudo rm -rf /opt/forge-node /etc/forge-node /var/lib/forge-node /var/lib/forge-node-priv /var/log/forge-node-priv /var/log/forge-node-agent /run/forge-node
sudo userdel forgenode
docker ps -a --filter label=forge.managed=true --format '{{.Names}}'   # forge-owned containers are NOT removed automatically; list and decide
```
**Proof that nothing KMU/Trading changed:** run before the install and again after the uninstall and compare: `systemctl list-units 'kmu-*' 'tradebot-*' 'secmpro*' --all --no-legend | awk '{print $1,$3,$4}' | sha256sum`; `docker ps -a --format '{{.Names}} {{.Image}}' | sort | sha256sum`; `git -C /opt/kmu-ai rev-parse HEAD`; `stat -c %Y /opt/kmu-ai /srv/models`. T0 `inv.*` stores the same evidence automatically.
7. **Broken install safety:** the open root-capable SSH session during install is the anchor; there is no sudoers change, so a mistake cannot lock `sudo` out.

### 14.2 F7a — measurement (ROADMAP: "Festlegung erst nach Messrunde")
**M1 passive (part of this use case, T0 only):** `metrics.sample` every 30 s for **72 h** per host covering at least one weekday, one pipeline run if any occurs, the 21:30 forge backup and the 03:00 KMU backup (sampling inside the window is light T0 and permitted): GPU util/VRAM/temp/power/clock/throttle reasons per card and **per compute process**, CPU/RAM/swap/load, disk I/O and queue depth **per device** (system disk vs the KMU model SSD — observed from `/proc/diskstats`, never by touching `/srv/models`), PCIe link state, NVMe wear/temperature only where sysfs exposes it (`smartctl`/`nvme-cli` absent ⇒ `unavailable`). **M2 active (separate, only on carlgpu2, only with owner go):** a T1 job writes a **20 GiB test file into the forge root volume on the system disk** (`/srv/forge/node/measure/`; bounded by the volume's fixed size, so the volume must be grown first by `volume.grow`/the install value; g2 has ≈1.2 TB free) and measures sequential write/read at `ionice -c3` — this characterises the **system disk**, which is where the Fabrik data lives until R1 (OQ-1).
